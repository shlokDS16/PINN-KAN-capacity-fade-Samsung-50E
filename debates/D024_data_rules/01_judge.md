## 1. FB-5 gap rule (question 1)

**What the throughput coordinate needs.** The coordinate is discharged charge divided by 4.9 Ah, integrated by the trapezoid rule. A gap loses or invents throughput only if current can be non-zero inside it. If both endpoints are at rest (|I| <= 0.05 A) the integral over the gap is 0 whatever its length. If an endpoint is active the trapezoid integrates a ramp across the gap: a real pause that follows a current sample (a 3 h tempering pause) invents throughput, and missing data loses it. So the gap that matters is a gap with an active endpoint; this is exactly the `dt_max_active_s` definition in `samsung_full_audit.py` line 196 (either endpoint above 0.05 A, which also catches a rest-to-current transition).

**Why 0.05 A and 600 s.** The smallest designed current is C/20 = 0.245 A, so 0.05 A is five times below any designed current. At 10 s sampling while active (median 10.005 s, 75th percentile 10.015 s) a gap of 600 s is 60 samples. Its worst-case error is at most 600 s x C_dch / 3600 EFC (0.33 EFC at 2C); against the shortest cycling interval (one week, about 20 % duty) that is below 0.5 % of the interval, ten times under the 5 % median tolerance of the FB-5 validation and twenty times under the 10 % last-check-up tolerance. The 600 s value was already the code constant, so no number is chosen after seeing the data.

**Why not the any-gap rule.** It flags 1370 of 1893 files (72 %) and leaves 9 cells fully logged, one laboratory. Of the flagged files, 936 have a rest-only gap between 10 900 s and 42 500 s (3 to 11.8 h), which is the designed long rest of the cycling protocol, and 1355 have the long gap in rest only. The consequence would be self-defeating: every interval with such a file falls back to the designed (analytic) throughput, so the "ZYK-logged" branch would be analytic for most intervals, the validation could compare only 9 cells, and the prereg coverage condition (2 cells per DoD class and laboratory) could not be met. It is also not what 3.3(4) says: only "segments with missing log data" fall back.

**Evidence that the active-gap rule finds the real losses.** The incomplete files under the ruled definition are the dataset paper's data-loss incidents, by identifier: stage 1 file 4 of TP_z19_01 (fewer than 10 rows; paper: cycling data missing), file 22 of TP_z21_01, TP_z24_01, TP_z25_02 (gap of about 768 350 s, 8.9 days; paper: partially missing), file 16 of TP_z16_02 (lab blackout); stage 2 file 24 of z04 to z11 cells (9 files with 620 to 997 s active gaps; paper: 2 days missing), file 22 of TP_z03_01 and TP_z03_02 (10 800 s, 3 h), files 22 of TP_z23_01 and TP_z24_02 (time not monotonic). Rest-only gaps never exceed 11.8 h (0 files above 24 h), so no multi-day hidden window sits behind a rest-only gap in this release.

**The 6 ZYK metas without csv** are TP_z01_01, _02, _03 and TP_z03_01, _02, _03, all stage 2, all file 24: this is exactly "TP_z[01,03]_*_24_ZYK: Tester malfunction. Cycling data missing. Cycling itself was performed correctly for 33 days" in the paper's stage 2 list. Rule: they remain `missing_file` rows (incomplete); the interval between the two surrounding check-ups takes the designed throughput (3.3(4), last sentence); the check-ups stay in training and scoring; those intervals do not enter the FB-5 validation (their source is not "logged"). The six cells are not excluded.

**Counts under the ruled rule** (recomputed from `zyk_files.csv` and the table flags): 18 read files are incomplete (15 active gap, 2 non-monotonic time, 1 with fewer than 10 rows), in 18 cells; the 6 `missing_file` rows add 4 more cells (TP_z01_01, _02, _03 and TP_z03_03, stage 2; TP_z03_01 and _02 stage 2 are already among the 18). So 22 cells have an incomplete file and **125 of 147 cycling cells are fully logged** (the steward's 129 counted only read files). Fully logged cells per DoD class (edges 0.15, 0.35) and laboratory, classes low/mid/high: HM 15/9/38, INT 25/13/13, SIE 3/6/3. Every class-laboratory cell has at least 3, so the prereg coverage condition (at least 2) holds, narrowly for SIE.

**DoD classes (undefined in PREREG 5).** Fix `DOD_CLASS_EDGES = (0.15, 0.35)` now: low = DoD 0.05, 0.10, 0.15; mid = 0.20 to 0.35; high = 0.40 to 0.60. These come from the design values, were in the code before any validation was run, and the validation uses throughput only.

**Rejected alternatives.**
- Any gap above 600 s (current code): see above.
- 60 s while active: flags 46 files instead of 15. Error bound is 10 times smaller than needed, and it flags 31 files only for gaps of 60 to 600 s whose worst-case effect is below the tolerance. Kept as an information row, not the rule.
- A cell-dependent threshold in EFC (gap x C_rate / 3600 above some fraction of the interval): more principled in form but adds a cell-dependent parameter and an arbitrary fraction, and cannot change the conclusion, because the rule already catches the documented incidents. Revisit only if the validation fails by a margin that the gap rule could explain.
- Treat the six missing files as exclusions: contradicts 3.3(4) (check-ups of segments with only missing log data are kept).
- Interpolate across active gaps: invents data; the prereg states the fallback.

**Validation reporting.** `python -P -m pinnkan.zyk --validate` is run once, with the ruled definition, after the rebuild. The verdict is the one of PREREG 5 (median <= 5 %, no cell above 10 % at its last check-up). It is reported also, as information only, at 60 s and under the any-gap rule. If it fails, ZYK-logged throughput is used for every cycling cell (the prereg branch), with the per-interval fallback above for the 22 cells. The earlier 24 % median on 12 INT cells stays labelled informational, as the steward wrote. Note the validation sample (125 cells) covers all three laboratories only because of this rule; SIE has 3 to 6 cells per class, so a single SIE cell above 10 % at its last check-up rejects the analytic branch by the prereg rule, as written.

## 2. Retention anchor (question 2)

**Ruling: Q0,c = the ET_T23 capacity of every cell**, from the same step-21/22 protocol as every check-up.

- PREREG 3.3(2): "ET_T23 capacity if ET members exist for every analysed cell, otherwise the first quality-passed CU for every analysed cell (one reference for all; by availability)". The condition holds: ET_T23 exists for all 279 cells (279 rows) and passes QC for all 279 (RESULT section 4). The fallback is not used. PREREG 3.3(2) also says the then-current output was anchored on the first CU only because the ET files were not yet on disk.
- Dataset paper (note, Data section): "relative capacity Q_rel = Q_i / Q_0 with Q_0 from the initial RPT (ET)". Anchoring on ET follows the data authors' definition and keeps the first window point informative: with a first-CU anchor every cell's first retention is exactly 1 and the early fade (the first weeks, the largest source of between-cell difference in the window) is unmeasured, which PREREG 3.3(2) already says.
- Caveat to print, not a reason to change: the note lists the ET ambient temperatures as "10, 45, 23 C" and the authors warn that AT_T23 may deviate because of the earlier 10 and 45 C tests. I did not verify the order inside ET; if ET_T23 follows the other two, every cell carries the same one-time offset, which is absorbed into Q0 identically for all cells and arms.

**Rejected: first quality-passed CU.** It loses the early fade, makes retention at the first window point identical for all cells, and departs from the data authors' Q_rel. It is cheaper only in that it needs no ET file, which is no longer a constraint.

**Rules attached.**
- The availability test is decided once, on the ET_T23 rows of the analysed cells before the outlier and incident steps, and the result is written to the run record (all 279 present). The loader must not re-decide it from rows that survived incident drops (see the defect in section 0 and ruling 5).
- `retention_vs_first_cu` stays as a descriptive column. A first-CU anchor row may be added to 9.9 as a descriptive appendix row without consequence, only if CPU remains after the core set.
- Related structural check (Action C5): the dataset paper's incident "TP_k[08-11]_[01,04]_01_ET_T23: discharge without CV phase, repeated capacity measurement replaced the failed cycle; charge OCV may be corrupted". PREREG keeps these ET files. The four analysed cells are TP_k08_01 to TP_k11_01 (stage 1; the 04 cells are not analysed). `analyse_capacity_csv` sums all runs of a step (`q21_ah`, `q22_ah` are sums, `main` is only the longest). The steward confirms from structure (run count, durations, step order, not values) that the ET capacity of those four cells comes from the repeated cycle alone, by a rule fixed now: use the last complete charge-plus-discharge pair in the file. If the file has a failed run besides the repeated one, the pipeline must not add them.

## 3. Do exCU rows enter the causal outlier rule? (question 3)

**What the rule is for** (PREREG 3.3(3)): to remove an isolated measurement error from the series of capacity measurements of a cell without removing real fade, including knees, using only earlier points so that window membership never depends on later labels. Its object is the sequence of capacity measurements made at 23 C with the identical step-21/22 protocol; ET_T23, CU and exCU all are such measurements and exCU rows are forecast points (5: "all CU and exCU after the window").

**Ruling: the series is every ET_T23, CU and exCU row of the cell in file order; AT is excluded** (3.3(6); contaminated by the 10 and 45 C tests). This is what the code does (`series = kind != AT`). The two CU rows that flip from pass to flagged are a consequence of the rule meeting a denser, complete series, not a change of the rule. They stay flagged, and no one inspects them: looking would need capacity values, and restoring them after seeing the effect would be an outcome-based choice. The retain-every-check-up row (9.9 (h), a downgrade row) covers the rule.

**Why not exCU-excluded.** Either the exCU rows would go untested while being scored, or they would be tested against a series that skips the most recent measurement, with a longer dt and a stale fall rate. Both are worse than testing every measurement against its two latest valid predecessors.

**Why not "keep the CU-only series because the thresholds were set on it".** True and to be disclosed: the thresholds (3.0 x fall rate, 1 %) were fixed on 163 check-ups of 19 cells parsed from CU files only (BLINDING_LOG, 2026-11-05 00:09). The final data use ET_T23, CU and exCU. Thresholds are not re-tuned (that would use the data they test). PREREG 3.3(3) and (10)(a) add the sentence: "the rule was developed on CU rows; in the final data ET_T23 and exCU rows enter its series, and the thresholds were not changed after the full release."

**One consequence to expect, not to fix.** ET is the first valid point and is never tested; the first CU is tested for a rise only. A rise of more than 1 % between ET_T23 and the first CU is the only way the ET anchor can create a flagged first window point. The steward reports, as aggregate counts by kind (not by cell, no values), how many rows of each kind carry `capacity_outlier_vs_neighbours` (RESULT already counts 5 in total), so the paper can state it.

## 4. Lab-map tie rule (question 4)

**Facts (identifiers).** 40 cycling conditions; majority labs HM 17, INT 19, SIE 4 with the current alphabetical tie-break. Three conditions mix laboratories, all stage 2: T23|SOCmax0.8|DoD0.25|Cch0.2|Cdch1.4 (INT 3 cells from TP_z07, HM 3 from TP_z12; an exact tie), and T45|0.8|0.6|0.24|2 and T45|0.8|0.6|1|2 (HM 6, SIE 3, clear majority). These counts, and the simulation of 9.3 ("labs HM 17 / INT 19 / SIE 4", 100 000 replicates), the unit tests (`test_pk_v2_rows.py` 170, `test_pk_v2_stats.py` 332) and PREREG 9.1 all use the HM-17 map.

**Where the map is used.** (a) the lab-stratified downgrade row (9.8 (i)): stratum = majority lab, weight 1/3 per laboratory; (b) per-lab descriptive rows and the group labels of the dependence report (`stats_v4`); (c) the synthetic laboratory offsets of the extraction calibration; (d) subset composition tables. **Not used by the lab-and-stage indicator row (9.8 (ii)):** the indicators are built per cell in `batch_from_cells` from the cell's own laboratory, so the tied condition's cells carry their own lab there and the tie has no effect on that row. The tied condition is also useful identification there, because the same stress is run in two laboratories in one stage.

**Ruling.**
1. The map is computed once, from the design table (`samsung_cells.csv`: all cells of the condition, regardless of QC, scoring or blinding exclusions), by: most cells; an exact tie goes to the laboratory with more cycling cells in the whole design (HM 69, INT 60, SIE 18); if still tied, alphabetical.
2. It is written to `runs/prereg/lab_map.json` with its sha256 and the list of the three mixed conditions (cell counts per lab), committed before FROZEN. Every consumer reads that file. The three present implementations (`extraction_calibration.majority_labs`, `metrics.train_condition_meta`, `stats_ext.majority/condition_strata`) count different things (all cells, training cells, "scored cells") and each breaks ties alphabetically; they are replaced by the file. A count over scored cells could flip a stratum after a blinding exclusion or a QC drop; a fixed design map cannot.
3. Result of the rule: the tied condition is HM, so HM 17 / INT 19 / SIE 4 stands and nothing in PREREG 9.1, the simulation or the tests changes. The text of 9.1 changes from "the 3 mixed-lab conditions go to their majority lab" to the explicit rule with the exact tie named.
4. Effect on the lab-stratified row: one condition of 40 sits in the HM stratum (weight 1/51 within a 1/3 laboratory weight). Under the alternative assignment (INT) the weights would be HM 1/48, INT 1/60. The row is also recomputed under the INT assignment as a **descriptive sensitivity in 9.9 (a)** with no consequence for any tier; the downgrade row uses the frozen map only. Per-lab descriptive rows disclose that two HM-assigned conditions contain 3 SIE cells each and the tied one 3 INT cells.
5. Effect on the lab-indicator row and Test C: none.

**Rejected alternatives.**
- A fourth "mixed" stratum: one condition in its own stratum, which breaks "weight 1/3 per laboratory" (the row would weight a single condition at 1/4 or need a new weighting rule), and a bootstrap stratum of size 1 is degenerate.
- Excluding the tie from the lab-stratified row: the row would run on 39 conditions while the primary runs on 40; an estimand mismatch in a row meant to test the same estimand.
- Fractional membership (half HM, half INT): the most faithful, but requires a different bootstrap, non-integer strata sizes and a change of the 9.1 text and the simulation labels; the gain is one condition.
- The lab of the earlier stage: both stage 2, undefined.
- Tie to INT, or keep an unnamed alphabetical default: INT would change the counts to 16/20/4 and need the simulation labels, tests and text redone for no outcome-independent benefit; an unnamed alphabetical default is what produced the divergent implementations.

## 6. The 49 INT cells whose meta serial contradicts the design table (question 6)

**Reading.** The meta internal serial is the physical cell serial typed at the tester; `serial_internal` in the design table is a lookup. The condition of a cell comes from its zip name (TP, cell), the `Testpoint` field of the meta and, for cycling cells, the files it contains (ZYK files present, with the cycling current). Stage was decided by laboratory, first date and, where present, the `_MKII` tag with 0 disagreements. The pattern (a permutation within INT, e.g. the meta of TP_z04_01_s1 carries the design serial of TP_k04_04_s1) points to an INT-side bookkeeping error in serial registration, not to data filed under the wrong condition. The only design-table fields that follow the serial are `m_0`, `R_1khz_0`, `U_0`, which the pipeline does not use for any analysis (only as the optional cross-check of the stage vote).

**Ruling.**
- No exclusion, no re-assignment. Excluding 49 of INT's 102 cells (60 cycling, 42 storage) on a bookkeeping field that nothing downstream reads would remove data on no ground and would unbalance the laboratory strata.
- `serial_internal` is not used as an identifier anywhere; the cell identity is `cell_id = <zip serial>_s<stage>`. Add a column `meta_serial_conflict` (True for the 49) to `samsung_cells.csv` for reporting.
- Disclosure sentence in Methods (data): "For 49 cells of one laboratory the serial inside the metadata differs from the design table; condition and stage of these cells follow the file names, the Testpoint field, laboratory and dates, which agree for all 279 cells."
- One check that can falsify the reading, using logged current only (no capacity): for every cycling cell, the median discharge current of its complete ZYK files (samples below -0.05 A) against C_dch x 4.9 A of the zip-name condition. A cycling cell deviating by more than 10 % is a condition-identity disagreement and is **excluded and listed under 3.2** (rule fixed now, before the check is run). The check costs nothing extra, because the ZYK table rebuild reads those files anyway. Storage cells cannot be checked this way; their identity rests on the zip name and the Testpoint field. This also treats the `Testpoint` field of TP_k03_04, _05, _06 reading `k02noCU` as recorded.
- Sensitivity row: none added (the 9.9 list is long and these cells enter every row alike). If the identity check finds a mismatch, the lead reopens D024.

## 7. What would reopen this decision

- The identity check finds one or more cycling cells whose logged current contradicts their zip-name condition.
- The aggregate flag counts by kind show the exCU or ET rows account for more than a handful of the flagged rows, or the first-CU rise flag after ET is systematic (more than 10 % of cells).

## 9. Reasons in short, for the ledger

The gap rule is chosen by what the coordinate can lose (throughput only moves with current), is backed by agreement with the dataset paper's own incident list, and avoids a rule that would have made the logged branch vacuous. The anchor follows PREREG's availability rule and the data authors' Q_rel. The outlier series is every 23 C capacity measurement because the rule is about measurements, and a post-hoc restore of two rows would be an outcome-dependent choice. The lab map is made a frozen file so that the number the simulation used is the number the analysis uses. The stage of the incident files is read from the paper's headings. The serial conflict is a bookkeeping field that no analysis reads, and one current-based check tests the reading.
