## What was built
1. **Pin change.** `guard.PIN_FILES` = {subsets, symbolic_library}. `build_freeze_payload(..., item_f_config_paths)` writes `item_f_config_sha256s`; with `require_pins=True` it needs five distinct configs, otherwise the shortfall is listed as `pins_missing: ["item_f_configs"]` and `verify_freeze` refuses such a FROZEN. The `verify_freeze` message names the five item (f) run configs, not the file.
2. **`stats_v4.build_item_f(root, run_dirs, ...)`.** Refuses (`ItemFError`) when: the freeze is invalid or HEAD is not the FROZEN commit (`guard.verify_freeze`); a run's `mode_effective` or `mode` is not `inner`; a run is not the g1 cell (Samsung, B, m 8, max-min); the config hash (recomputed from the run's recorded `config_input` with `run.DEFAULTS`) differs from the recorded one or is not in FROZEN `item_f_config_sha256s`; the folds are not exactly 0-4; SCORED.jsonl holds a Samsung row (or a row that does not say its dataset); any Samsung `condition_scores*.json` exists under `runs/`; the file already exists (append-only); or the estimate cannot be formed (one laboratory). It writes `runs/item_f/item_f_dependence.json` and the `.sha256.json` record with `frozen_commit`, `cell`, `contrast`, `folds`, `d_star_by_fold` and, per run, run_id, config hash and the sha256 of `config.json`, `tuning_done.json`, `inner_folds.json`, `comparators.json`, `train_condition_meta.json`. Estimator: `item_f_from_runs(run_dirs, ("D*", "A1"))`.
3. **`guard.require_item_f_record(root, runs_dir)`**, called in `run._run` right after `check_config_frozen`, only for `dataset == "samsung"` confirmatory runs, before the run folder exists and before `build_data` / `load_split`. Refuses on: record or file absent, file hash differs from the record, `frozen_commit` differs, folds not exactly 0-4, a run config hash not in FROZEN, artifact list not exactly the five, any artifact absent or differing. Returns the file's sha256.
4. **Ledger.** `record_scoring(..., dataset, item_f_sha256)`: a Samsung row without the hash is refused; rows now carry `dataset`. `stats_v4.require_item_f(..., ledger_root=)` requires at least one Samsung row, every Samsung row to carry the same `item_f_sha256`, equal to the file hash (and to `pinned_sha256` if given); the mtime check stays. `stats_step.run_stats_v4(..., ledger_root=)` and the CLI `--ledger-root` pass it through; when `ledger_root` is omitted but a FROZEN exists in the default root, the root is used, so the check cannot be skipped by omission.
5. **Smoke test** (`test_a5_smoke_...`): five synthetic four-arm (A1 A9 A11 A12) inner runs through `run.run` (g1-shaped config: m 8, max-min), laboratories relabelled to two in the fixture because synthetic data have one, then `build_item_f` (with `cell=` set to the synthetic cell, a parameter meant for this test only) and `require_item_f`.
6. **Concordance row.** `stats_v4.item_f_concordance(item_f_dirs, confirmatory_dirs)`: per fold, D* agreement, and for A1 and D* the `best_hp` equality, common-condition count, max absolute difference and Spearman correlation of the inner-CV `cond_scores`; `reopen_flag` is true when D* differs in more than one fold. Descriptive; reads training-side files only. Not yet wired into any script (the confirmatory g1 runs do not exist).
