## 1. The model as equations
Names: the repo calls the solution network `solution_u` (F in the notebooks' plot labels, `F(.)`), the dynamics network `dynamical_F` (G in the notebooks, `G(.)`). Same as Wang et al. (Nat. Commun. 2024) F and G.

- **Inputs.** One row per (cell, cycle k): 16 charge-segment health indicators x_k plus a 17th column "cycle index" t_k. After per-cell min-max scaling both lie in [-1, 1] (see section 3). Label y_k = SOH = capacity / nominal capacity.
- **Solution network** (`Model/PIKAN_opt.py:11-23,74`): u_k = F(x_k, t_k) = KAN_pred(KAN_enc([x_k, t_k])), encoder widths 17-60-60-32 and predictor 32-32-1 (efficient-kan, `:14-15`). Output is SOH.
- **Dynamics network** (`:75`): G = KAN [34, 60, 60, 1]. Input is the concatenation [x_k, t_k, u_k, u_x] (16 + 1 + 1 + 16 = 34; comment at `:75` says it is deliberately not 35, "does not include the partial derivative of u with respect to t"); `:167`.
- **Autograd derivatives** (`:152-165`): u_t = dF/dt at fixed x_k, u_x = dF/dx (16-vector), both with `create_graph=True`.
- **Residual actually implemented** (`:167-169`):
  f(x_k, t_k) = u_t(x_k, t_k) - G(x_k, t_k, u_k, u_x(x_k, t_k)).
- **Loss** (`:183-193`), with a pair (k, k+1) of consecutive stored cycles of one cell as one sample:
  - L_data = 0.5 MSE(u_k, y_k) + 0.5 MSE(u_{k+1}, y_{k+1})  (`:183`)
  - L_PDE = 0.5 MSE(f_k, 0) + 0.5 MSE(f_{k+1}, 0)  (`:186-187`)
  - L_phys = sum over the batch of ReLU[ (u_{k+1} - u_k) (y_k - y_{k+1}) ]  (`:190`; a **sum**, not a mean, so its weight scales with batch size 256/512)
  - L = L_data + alpha L_PDE + beta L_phys  (`:193`)
- **Weights.** Default alpha = 0.7, beta = 0.2 (`main_our_models_optimize_XJTU.py:248-249`) but **never used as defaults in the reported runs**: every reported run searches the 7 x 7 grid {1e-3, 1e-2, 1e-1, 1, 10, 100, 1e3} for both (`:250-251`, loops at `:121-122`) �?" see section 6.
- **Constraint semantics.** L_phys is not the monotonicity penalty of the PINN4SOH paper (ReLU(u_{k+1} - u_k)). It multiplies the predicted difference by the **true** label difference, so it penalises "predicted step has the opposite sign to the true step", in both directions: it penalises a predicted decline when the label rises (capacity regeneration) as well as a predicted rise when the label falls. It therefore uses test-time-unavailable information (label differences) and encourages the network to reproduce label noise and regeneration spikes in training. It is not a monotonicity constraint on the model (inference of mine from `:190`; the code comment says "considering capacity regeneration").
- **Difference from PINN4SOH.** PINN4SOH feeds u_t into G as well (35 inputs; `refs/code/_dl_PINN4SOH/raw/Model/Model.py:232`), which makes the PDE residual trivially solvable by G = identity on u_t. PIKAN removes u_t from G's input, so its residual is not trivially zero. This is a real fix, credit it, and it is where the PIKAN "physics" first differs.

## 3. Data
- **Datasets** (README section 4, `Data/`): XJTU (55 cells, 6 batches/protocols, NCM), TJU (130 cell files in 3 batches NCA / NCM / NCM+NCA), MIT/Severson (125 files, 3 batches, LFP), HUST (77 files, LFP). I.e. the four PINN4SOH feature tables; no other dataset is used anywhere in the repo.
- **Feature files:** per-cell CSVs with 16 columns + `capacity` (header in every file, checked): voltage mean, std, kurtosis, skewness, CC Q, CC charge time, voltage slope, voltage entropy, current mean, std, kurtosis, skewness, CV Q, CV charge time, current slope, current entropy. These are the Wang et al. features: statistics of voltage in [V_end - 0.2 V, V_end] and of CV-stage current from 0.5 A to 0.1 A (Wang et al. 2024, Methods "Feature extraction"). The 17th input is "cycle index".
- **Label:** SOH = capacity / nominal capacity with nominal 2.0 (XJTU), 1.1 (HUST, MIT), [3.5, 3.5, 2.5] (TJU batches) (`dataloader.py:57,191-194,268-270,316-318`).

The XJTU_Dataloader notebook output (cell 5) prints the normalised cycle index running linearly from -1.000 to +1.000 over 371 cycles. Hence **t_k = -1 + 2k/(N-1) = fraction of the cell's total life**, and every test cell is scaled by its own end-of-life cycle count and its own whole-life feature ranges. (The dataloader's own `__main__` default is z-score, `:359`, not used by the scripts.)
- **3-sigma filter (`:18-42`):** drops any row where **any** column, including `capacity` (the label), lies beyond mean A� 3 sd of that cell. Applied to test cells too, so the scored cycle set is chosen with test labels, and "consecutive" pairs (k, k+1) may skip deleted cycles.
- **Train / test cells (cell-level split, hard-coded):**
  - XJTU (`main_our_models_optimize_XJTU.py:18-24`): within one batch, any file name containing the character '4' or '8' is test, all else train. For 2C, R2.5, R3, RW, satellite that is cells 4 and 8 (2 test, 6 train); for 3C it also catches `3C_battery-14`, giving 3 test cells (12 train). Train and test are the same protocol (same batch). Test set per batch is 2-3 cells.
  - HUST (`main_our_models_optimize_HUST.py:13-17`): 20 listed ids are test, the remaining 57 train.
  - MIT (`main_our_models_optimize_MIT.py:20-25`): per batch, cell id divisible by 5 is test.
  - TJU (`main_our_models_optimize_TJU.py:13-33`): units digit 5/9 (batches 1, 3) or 4/8 (batch 2) of the file order index (OS directory order) is test, within batch.
  - small sample (`train_list[:small_sample]`, n = 1..4): first n files of an unsorted `os.listdir`, i.e. an OS-dependent and unreported choice of cells.
- **Can test-cell data reach training, tuning or early stopping?**
  1. Training/validation: both come from **training cells only**; the validation set is a **random 20 % of consecutive-cycle pairs** of the training cells (`dataloader.py:158-159`, `random_state=420`), so validation pairs are neighbours of training pairs from the same cell. Early stopping and checkpoint choice use this near-duplicate validation MSE (`PIKAN_opt.py:224-228,243`), not test. Test cells do not enter training.
  2. **Hyper-parameter selection uses the test set** (confirmed, `main_our_models_optimize_XJTU.py:121-145`): for each seed, 49 (alpha, beta) pairs are trained and the pair with the lowest **test MAPE** is kept (`if metrics[1] < best_MAPE`, `:138`); its test predictions, parameters and hyper-parameters are saved as `best_results`, and the README tables are the mean of those (aggregation `results_analysis_code/Model_optimize_XJTU_results.py:31` reads `best_results`). The same pattern is in the HUST, MIT, TJU scripts. Authors also released per-group means over all 49 pairs (`*_group_mean.xlsx`), see section 5.
  3. Per-cell normalisation, 3-sigma filtering and the t-feature (above) use whole-life information of each test cell.
  4. Transfer: the per-target fine-tuning learning rates are hard-coded per pair without any stated selection rule (`main_our_models_fine_tuning.py:244,257`; the fine-tuning early-stop patience is 10, `:315`), selection method unknown.

## 4. Training
- Optimiser: Adam for F with the schedule 30 warm-up epochs from 2e-3 to 1e-2 then cosine to 2e-4 over the remaining epochs of 200 (`Model/PIKAN_opt.py:31-57,78,81-86`; defaults `main_...XJTU.py:235-241`); Adam for G with constant lr_F = 1e-3 (`:79`; XJTU, `:241`; fine-tuning uses 1e-2, `main_our_models_fine_tuning.py:320`). Because early stopping (patience 20 on validation MSE, `:243`) will usually stop before epoch 200, the cosine tail may rarely be reached (not checked per run).
- Batch size 256 (XJTU), 512 (HUST, MIT, TJU), 128 for small-sample (`main_our_models_optimize_XJTU.py:231,168`). Epoch = full pass over training pairs. No gradient clipping.
- Early stopping criterion: validation MSE of F on the random-pair validation split (`:135-148,224-246`); the test set is also evaluated each time validation improves, only for logging and for saving the test predictions (`:228-234`).
- Seeds: `set_seed(e)` for e = 0..9 �+' 10 seeds (`main_...XJTU.py:111-112`); `utils/util.py:21-35` also sets cudnn deterministic. Interpretability notebooks use seed 25 (single run). README gives means only, no standard deviation; the released xlsx contain per-seed rows so a spread can be recomputed.
- Baselines (`main_comparision_*.py`): MLP, CNN, KAN (same 17-60-60-32-32-1), KAN-medium, Transformer, trained once per seed, **single configuration, no (alpha, beta)-type search, early-stopping patience 10 vs 20 for PIKAN/PINN** (`main_comparision_XJTU.py:103`; PIKAN `--early_stop` default 20, `main_our_models_optimize_XJTU.py:236`). The PINN baseline is the same 49-point test-selected search as PIKAN (`Model/PINN_opt.py`, run through `main_our_models_optimize_*`).

## 6. Hidden assumptions, bugs and weaknesses (concrete)
1. **Test-set hyper-parameter selection.** Best of 49 (alpha, beta) per seed by test MAPE (`main_our_models_optimize_XJTU.py:121-145`, the other three datasets likewise). The authors' own `group_mean` workbooks (`processed_results/results_soh-estimation/PIKAN_opt/PIKAN_opt_*_results_group_mean.xlsx`, columns idx / MAE / MAPE / RMSE, my summary with a stdlib xlsx reader, all means over 10 seeds): for the best README row 0.0031 (XJTU b1) the median group is 0.0042 and the mean 0.0049; XJTU b2 best 0.0089, median 0.0125; HUST best 0.0057, median 0.0083; TJU b1 0.0088 vs median 0.0106. For the PINN baseline the gap is far larger (XJTU b1 best 0.0060, median 0.0242; HUST best 0.0078, median 0.0202). Best-of-grid is selected on the test cells, so the published row is optimistic by an unknown amount; the group medians show PIKAN is far less sensitive to (alpha, beta) than the sine-MLP PINN.
2. **Physics terms add little.** With alpha = beta = 1e-3 (group 1; essentially no physics) PIKAN's mean test MAPE is 0.0037, 0.0126, 0.0077, 0.0068, 0.0100, 0.0062 on XJTU b1-6, 0.0065 HUST, 0.0061 MIT, 0.0102 / 0.0136 / 0.0058 TJU b1-3, versus the data-only KAN row of the README (0.0041, 0.0126, 0.0081, 0.0064, 0.0157, 0.0062; HUST 0.0064; MIT 0.0060). The "best group" per batch picks alpha/beta all over the grid (e.g. XJTU b1 alpha = 0.01 beta = 0.1; b2 alpha = 100 beta = 10; b3 alpha = 0.001 beta = 0.1) with no consistent pattern. Together with the single-run KAN vs PIKAN comparison in section 5 this suggests most of the gain over PINN comes from replacing a sine-MLP by a KAN (and 10x more parameters), not from the physics; the repo contains no controlled ablation for it (the paper may; not read).
3. **The "PDE" residual is not a battery physics law.** G is a free network trained by the same optimiser; the residual forces F's �^,/�^,t at fixed features to agree with G's output. Nothing ties G to an observed �^,SOH/�^,cycle. The cell's SOH changes with k both through t and through the drifting features x_k, so the physically meaningful rate is the total derivative u_t + u_x . dx/dk, not u_t alone at fixed x. The pair (x_k, x_{k+1}) is available in the data loader but is not used to build a total-derivative residual (inference from `PIKAN_opt.py:152-170`, `dataloader.py:77-83`).
4. **Time variable is life fraction, not cycles.** Per-cell min-max (`dataloader.py:58-65`; notebook cell 5 output) makes t = -1 + 2k/(N-1). Consequences: (a) the model needs each test cell's end-of-life cycle count N (and whole-life feature ranges) to scale its inputs, i.e. estimation is not causal/online; (b) �^,u/�^,t and the discovered G are rates per unit **normalised life**, so a cell that lives twice as long has half the rate; "dynamics shared across cells/batteries" and "cross-battery transferability" of an equation are then comparing rates in different time units; (c) a 2-input model [one HI, t] already reaches MAPE 0.36 % on XJTU b1, which says life fraction alone carries much of the signal; the repo has no t-only baseline. (I treat (c) as a control we must run in our own work, not as our contribution.)
5. **The discovered "degradation laws" are not stable across datasets.** Prior-guided G(u), fitted per dataset (`*_PDEAutoDiscovery.ipynb` cell 28): XJTU 0.3067 (u + 0.6144)^2 - 0.7876; HUST 0.5289 (0.0146 - u)^2 - 0.6422; MIT 9.9945 (u - 0.9476)^2 - 0.0092; TJU 0.4035 (0.2592 u - 1)^2 - 0.3959. The Verhulst parameters computed for XJTU (cell 30) are r = -0.983, C = -2.217, K = 0.988: a lower asymptote C = -2.2 is not a physical SOH asymptote. Curvature, vertex and sign differ strongly between datasets (and the MIT curvature is 30 times the XJTU one). The README's "structural similarity to existing electrochemical models" is a claim about a parabola in u, chosen by hand (`fix_symbolic(...,'x^2')`, "Best value at boundary" printed).
6. **Symbolic formulas are numerically fragile and not interpretable.** The direct-symbolisation F is a sum of four sinh/cosh terms with coefficients of order 1e-4 to 5e-3 and arguments near -9 (cell 25), nested bessel/sinc/arcsinh; rounding to 4-5 digits changes MAPE from 0.0042 to 0.146 (XJTU direct symbolisation, `PIKAN_XJTU_Var2` cell 29), and for the prior-guided variant from 0.0058 to 0.101 (XJTU), 0.0089 to 0.215 (HUST), 0.0083 to 0.072 (TJU); MIT is unaffected (0.0076). No sparsity regulariser is used during training, so the pykan symbolic step operates on a dense, unpenalised network.
7. **Metric argument order bug (all tables).** `utils/util.py:80` defines `eval_metrix(true_label, pred_label)` but every call site passes `(pred_label, true_label)` (e.g. `Model/PIKAN_opt.py:231`, `main_our_models_optimize_XJTU.py:80`), so sklearn's MAPE divides by the prediction instead of the truth. MAE and RMSE are unaffected. Small numerical effect for SOH in 0.7-1.0 but it is selection-relevant, because MAPE is the criterion that picks the best (alpha, beta). The same call order appears in PINN4SOH, so published baselines share it. The notebooks call `eval_metrix(true_label, pred_label)` correctly in the symbolic comparison cells but incorrectly in `Test` cells.
8. **Validation = neighbours of training pairs** (random pair split, `dataloader.py:158-159`), so validation MSE is almost a training metric and early stopping behaves as a training-loss stopper (consistent with the model fitting without overfitting alarms). PINN4SOH's paper says it divides "training, validation and test batteries" 6:2:2 (Wang et al. text near Table 2) while the released code splits validation by pair, not by cell: paper and code disagree there.
9. **Unequal tuning in the headline comparisons** (section 4): PIKAN and PINN get a 49-point search on test; MLP, CNN, KAN, Transformer get none, and a shorter patience of 10.
10. **Tiny test sets**: 2-3 XJTU test cells per batch, test cells fixed by file name; the 10 seeds vary only initialisation and the pair shuffle, so the stated stability is not cell-sampling variance. No confidence intervals or paired tests anywhere.
11. **Seed-dependent, OS-dependent selection of small-sample training cells** (`os.listdir` order, then `[:n]`).
12. **Unsafe artefacts:** `.pt` / `.pth` files are pickles loaded with `torch.load` (default, no `weights_only`), do not load them; the environment file pins old versions (`pikan.yaml`, python 3.10, pinned pip list, Chinese mirror).
13. **Code state not matching README claims**: `main()` in `main_our_models_optimize_XJTU.py:108` runs only batch index 5 ('satellite', `range(5,6)`), `main_2()` only batch 0; the README tables for batches 1-6 imply editing the loops (the repo state is a mid-experiment snapshot). Default `model_name` argparse `choices` omit `PIKAN_opt` (`:220`), but the code sets the attribute afterwards.

## 7. What the method cannot do
- **No forecasting.** It maps features of the charge segment of cycle k (and t_k) to SOH_k. It cannot predict a future trajectory, EOL, or RUL; and since t is life fraction it cannot even be applied to a cell whose total life is unknown. (Their abstract says "estimation", the notebooks call the estimates "forecast".)
- **No extrapolation beyond observed cycles** (inputs normalised by whole-life range; nothing generates unseen cycles; the G network is never integrated forward).
- **No interpretable degradation law in a usable sense**: the symbolic G is a dataset-specific parabola, F's symbolic form is a fragile sum of hyperbolic functions (section 6, items 5-6).
- No temperature, C-rate, DOD or protocol inputs (all that is encoded is 16 summary statistics), no uncertainty output, no handling of cells with missing charge-segment data.
- Needs full charge to V_end and CV down to 0.1 A (feature definition), so partial charging cannot be handled.

## 1. The model as equations
Paper notation: u = SOH, t = cycle, x = health indicators. Paper Eq. (1) u = f(t, x); Eq. (2) du/dt = g(t, x, u; ...) "explicit PDE"; Eq. (3)-(4): g is replaced by a network G, and H := dF/dt - G(t, x, u, u_t, u_x; theta) is the residual, with F(t, x) the solution network (text of Methods, "Physics-informed neural network"). Eq. (5) SOH_k = Q_k / Q_0. Eq. (6) L_PDE = sum_i H(t_i, x_i)^2. Eq. (7) L_data = sum (u_i - u_hat_i)^2. Eq. (8) L_mono = sum_j sum_k ReLU(u_hat_{k+1} - u_hat_k) (text extraction of the PDF is partly garbled; read as the sum over batteries j and cycles k). Eq. (9) L = L_data + alpha L_PDE + beta L_mono.

Implementation (`Model/Model.py`):
- **Solution network** (`:64-77`): encoder = MLP 17 -> 60 -> 60 -> 32 with **sin** activations and dropout 0.2 between hidden layers, then a predictor Dropout(0.2) - Linear(32,32) - sin - Linear(32,1) (`:51-62`). Input = 16 features + cycle index (all scaled to [-1,1], see section 3). Output u = SOH. Xavier-normal initialisation (`:79-86`).
- **Dynamics network** (`:138-141`): `MLP(input_dim=35, output_dim=1, layers_num=3, hidden_dim=60, dropout 0.2)`, with sin activations. Input is `cat([xt, u, u_x, u_t])` = 17 + 1 + 16 + 1 = 35 (`:232`).
- **Derivatives** (`:216-235`): `u_t = grad(u.sum(), t)`, `u_x = grad(u.sum(), x)`, `create_graph=True`; residual `f = u_t - G(...)` (`:234`).
- **Losses per pair of consecutive stored cycles (k, k+1)** (`:247-258`):
  - L_data = 0.5 MSE(u_k, y_k) + 0.5 MSE(u_{k+1}, y_{k+1})
  - L_PDE = 0.5 MSE(f_k, 0) + 0.5 MSE(f_{k+1}, 0)
  - L_phys = sum over the batch of ReLU[(u_{k+1} - u_k)(y_k - y_{k+1})]  (`:255`, a **sum**, label-dependent; differs from the paper's Eq. (8), see weaknesses)
  - L = L_data + alpha L_PDE + beta L_phys  (`:258`)
- Weights (alpha, beta) per script default: XJTU 0.7 / 0.2 (`main_XJTU.py:99-100`), HUST 0.6 / 0.1, MIT 0.5 / 0.01 (`main_MIT.py:30-31`), TJU 0.1 / 0.1 (`main_TJU.py:38-39`); small-sample XJTU uses alpha 0.5, beta 10 (`main_XJTU.py:56-57`). `main_MIT.py:85-97` keeps a `grid_search()` function (grid reduced to one point), so a grid search existed; selection criterion not visible. `fix.md` (Chinese, dated 2026-09) says the initial code version had bugs which were fixed, "so that the alpha and beta values are not consistent with those in the Supplementary File; other code unchanged". The bug is not identified.
- Monotonicity or other constraints: only L_phys above; no architectural monotonicity.
- Optimiser etc. are the same as PIKAN (see below); PIKAN's code is a direct fork.

## 3. Data
- **Datasets** (paper "Data generation", Table 1): XJTU (new, 55 NCM cells, 6 charge/discharge protocols, batches 1-6; 8 cells per batch except batch 2 with 15; LISHEN 2000 mAh, 4.2-2.5 V, room temperature), TJU (Zhu et al.: NCA, NCM, NCM+NCA; 25/35/45 C; 0.25-4 C), HUST (Ye et al.: 77 LFP cells, one charge protocol), MIT (Severson et al.: LFP fast charging, 30 C). Paper counts 310,705 samples of 387 cells (the repo file counts, checked in the PIKAN copy of the same CSVs, are XJTU 55, TJU 130, MIT 125, HUST 77 = 387, consistent with the paper).
- **Features** (paper "Feature extraction", `data/*/*.csv`): from the last 0.2 V of the constant-current charge voltage curve (V_end - 0.2 V to V_end) and the CV-stage current between 0.5 A and 0.1 A: mean, std, kurtosis, skewness, charge time, accumulated charge (CC Q / CV Q), curve slope, curve entropy for voltage and for current = 16 features. Plus cycle index. Columns in the files: voltage mean, voltage std, voltage kurtosis, voltage skewness, CC Q, CC charge time, voltage slope, voltage entropy, current mean, current std, current kurtosis, current skewness, CV Q, CV charge time, current slope, current entropy, capacity (checked in `refs/code/PIKAN/Data`, which redistributes the same CSVs).
- **Label:** SOH = capacity / nominal capacity (nominal 2.0, 1.1, 1.1, [3.5, 3.5, 2.5] Ah; `dataloader.py` same as PIKAN's).
- **Normalisation:** identical dataloader to PIKAN (the PIKAN version differs only by `.to(device)`, diffed): `read_one_csv` inserts `cycle index = arange(n)`, drops any row with a 3-sigma outlier in any column **including capacity**, then min-max scales all input columns **per cell** with that cell's whole-life min and max (`dataloader/dataloader.py:44-67`). So t is life fraction and the scaling of a test cell uses its end-of-life. The paper states only "min-max normalization is performed on the features ... in [-1,1]" (text under "SOH estimation"); the per-cell, whole-life nature of it is not stated there.
- **Split (cell-level):** XJTU: within a batch, files whose name contains '4' or '8' are test (`main_XJTU.py:14-18`), others train; HUST: 20 listed ids (`main_HUST.py:42-`); MIT: id % 5 == 0 (`main_MIT.py:42-46`); TJU: index units digit 5/9 or 4/8 (`main_TJU.py:57`). The paper says train / validation / test batteries are split about 6:2:2 and test batteries are "evenly distributed" (Tables S2-S6, not read); **in code the validation set is a random 20 % of consecutive-cycle pairs of the training cells** (`dataloader.py:158-159`, `train_test_split(..., test_size=0.2, random_state=420)`), not separate batteries. Test cells never enter training; validation does not have independent cells.
- Leakage-type issues: per-cell whole-life scaling and 3-sigma filtering with test labels; test metrics are computed whenever validation improves (logging only, `Model/Model.py:293-298`). Hyper-parameters alpha, beta, lr per dataset were chosen by an unreported rule (a `grid_search` function exists). Treat the published numbers as in-protocol and slightly optimistic; do not use this repo's protocol as ours.

## 4. Training
Adam for F: warm-up 30 epochs 2e-3 -> 1e-2 then cosine to 2e-4 (200 epochs max) (`Model/Model.py:94-120`, `main_XJTU.py:86-91`); Adam for G with constant lr_F (1e-3 XJTU, 5e-4 HUST, 1e-3 MIT/TJU); batch 256 (XJTU) / 512 (others) / 128 (small-sample); early stopping patience 20 on validation MSE of F (`Model.py:308`); best state kept at lowest validation MSE. **No random seed is set anywhere** (`utils/util.py` has no seeding function; each run is "repeated 10 times", paper text "Fig. 4b"), so reported means are not exactly reproducible (the README says so itself). Baselines MLP, CNN: same optimiser/schedule, one configuration, patience 10 (`main_comparision.py:106`).
Fine-tuning (`main_adaptation - fine-tuning.py`): load source model, freeze G, fine-tune F only on one target-domain cell (`small_sample=1`, `:220`) with a hand-set learning rate per target (`:242,254,268,276,297`), early-stop patience 10.

## 6. Hidden assumptions, bugs and weaknesses
1. **Degenerate PDE loss.** G receives u_t as an input (`Model.py:138,232`; paper Eq. 4 lists u_t among G's arguments) and the residual is u_t - G(...). G can satisfy L_PDE = 0 by copying that input, independent of any degradation physics. The paper's claim that G "learns the degradation dynamics" and "is independent of protocols and datasets" (frozen in transfer, Methods) is therefore not guaranteed by the loss. PIKAN removed u_t from G's input.
2. **Paper vs code: monotonicity loss.** Paper Eq. (8) penalises any predicted increase; code `Model.py:255` penalises sign disagreement with the true label step, in both directions, and is a sum over the batch. The paper does mention capacity regeneration, but the code term needs labels.
3. **Paper vs code: validation.** Paper: validation batteries (6:2:2 by battery). Code: random pair split inside the training cells.
4. **Not seeded**; alpha, beta, lr hand-set per dataset; post-publication bug fix (`fix.md`) with changed alpha/beta, so published supplementary hyper-parameters do not reproduce the released code.
5. **Per-cell whole-life min-max incl. cycle index** (same dataloader as PIKAN): t equals life fraction; needs end-of-life of the test cell. Shared with PIKAN (see `PIKAN.md` section 6.4).
6. **Features are summaries of a 0.2 V charge window and CV tail:** needs a full charge to V_end and CV down to 0.1 A. CC Q and CC charge time are collinear at constant current (the PIKAN notebook comment says "CC Q is equivalent to CC charge time at constant-current charging"), so the 16-feature input has duplicated information; high feature-SOH correlation within a dataset (paper Fig. 3b) is a within-dataset property, not a cross-chemistry one: the paper itself reports that correlation signs flip between NCM/NCA and LFP datasets (feature 9-10 and 11-16).
7. **Test-set evaluation at each validation improvement** (logging only) and small test sets (XJTU 2-3 cells per batch).
8. **Gains are concentrated in small-data settings:** the authors state that with many training samples (HUST, MIT) a same-size MLP or CNN performs comparably; the headline superiority is for XJTU and the 1-4 cell small-sample runs, whose test sets are 2-3 cells per batch.
9. **Metric argument order:** `eval_metrix(true_label, pred_label)` (`utils/util.py:42`) called as `eval_metrix(pred_label, true_label)` (`Model.py:296`), so MAPE divides by the prediction (MAE, RMSE unaffected). PIKAN inherits it.
10. Pickled `.pth` files; no LICENSE file in the repository (checked: none in `git ls-files`).

## 7. What the method cannot do
Same as PIKAN: no forecasting of future SOH or RUL, no use without the features of the target cycle, no extrapolation beyond observed cycles, no explicit degradation law (G is a black-box network; "stable modelling and prognosis" in the title refers to estimation stability; the paper's "prognosis" is not demonstrated as forecasting in the sections I read). No temperature, current-rate or protocol covariates beyond the 16 summaries. No uncertainty.

# Gaps left by PIKAN + PINN4SOH that a JES paper could close

Basis: `notes/code/PIKAN.md` and `notes/code/PINN4SOH.md` (full code reading; PIKAN journal paper NOT read, PINN4SOH Supplement NOT read). Retired topics are not proposed: nothing below is about how the evaluation split changes accuracy, or about conformal / uncertainty calibration. Leakage-free cell-level evaluation (all hyper-parameters tuned on training cells only, 5+ seeds, paired comparisons) is our standard practice; where a gap needs a control from the evidence (e.g. a t-only baseline), that control is part of the method study, not a claimed contribution. Each gap states a test whose outcome could be negative. Numbers cited are from the repo files named; none comes from a run of ours.

1. **Residual along the trajectory instead of at fixed features.** Both codes penalise u_t = dF/dt at fixed x (`PIKAN/Model/PIKAN_opt.py:152-170`; `PINN4SOH/Model/Model.py:216-235`), but SOH moves with k through both t and the drifting features, so the physical rate is the total derivative u_t + u_x . dx/dk. The consecutive pairs needed for a finite-difference total derivative are already built (`PIKAN/dataloader/dataloader.py:77-83`) and unused. Test: replace L_PDE by a total-derivative residual (and variants with a physics-informed G form), compare with the original residual at identical training cells, seeds and budget; endpoint: test RMSE/MAPE and whether the learned G now matches the finite-difference dSOH/dk of the data. Could fail if G stays unconstrained.

2. **Cycle-unit time and a causal formulation (forecast, RUL).** Both repos scale time per cell by whole-life min-max (`dataloader.py:58-65`; PIKAN notebook `XJTU_Dataloader` cell 5 prints t running -1 to +1 over 371 cycles), so the method needs each test cell's end of life and gives rates per unit life fraction. Neither can forecast (PIKAN.md section 7). Test: train with t in physical cycles and features from a causal window only, integrate G forward from the last observed cycles, report error at fixed horizons and RUL error in cycles against PIKAN-style estimation re-implemented under the same inputs. Needs a dataset with long trajectories (see 8).

3. **Mechanistic G with a KAN correction, with identifiable parameters.** PIKAN's G is a free KAN, and the prior-guided symbolic G differs wildly by dataset: XJTU 0.3067(u+0.6144)^2-0.7876, HUST 0.5289(0.0146-u)^2-0.6422, MIT 9.9945(u-0.9476)^2-0.0092, TJU 0.4035(0.2592u-1)^2-0.3959; Verhulst C = -2.217 for XJTU (`Notebooks/PIKAN_*_Var2_PDEAutoDiscovery.ipynb` cells 28-30). Test: constrain G to a known family (power-law / sqrt-time SEI growth with Arrhenius factor, logistic, knee model) in physical cycle units and let a small KAN learn only the residual; endpoint: are the fitted physical parameters stable across cells of one protocol (variance across cells and seeds, interval overlap), and does accuracy match the free G? Fails if parameters are not identifiable.

4. **Symbolic extraction that survives rounding.** In the PIKAN notebooks the extracted formula is a dense sum of sinh/cosh/bessel/sinc terms with coefficients 1e-4..5e-3; rounding to 4 digits moves MAPE from 0.0042 to 0.1458 (XJTU direct), 0.0058 to 0.1013 (XJTU prior-guided), 0.0089 to 0.2152 (HUST), 0.0083 to 0.0725 (TJU) (`PIKAN_XJTU_Var2.ipynb` cell 29; `*_PDEAutoDiscovery.ipynb` cell 33). No l1/entropy regulariser is used in training (PIKAN.md section 2). Test: train with sparsity regularisation and a restricted symbolic library (low-degree polynomial, exp, power) and report symbolic-to-network MAPE ratio after rounding to 3 significant digits, together with formula length; success criterion fixed in advance (e.g. ratio below 1.1).

5. **KAN basis ablation at matched parameters and tuning.** PIKAN uses one KAN family (efficient-kan B-spline, grid 5, order 3, ~10 parameters per edge) and 75,960 + 57,000 parameters against 7,781 + 5,821 for the PINN (`PIKAN/README.md` table 7.3); its own medium model (6,120 + 8,840) is roughly as accurate (README 7.1). kan-review lists ready implementations: Chebyshev (ChebyKAN), Gaussian RBF (fast-kan), Fourier, wavelet (Wav-KAN), Jacobi, rational (`kan-review/README.md` section 6). Test: same data, same inner-loop tuning on training cells, parameter-matched MLP vs 4-5 KAN variants in the PINN framework; endpoint: paired RMSE differences with confidence intervals across seeds. May show the KAN advantage is a capacity or smoothness effect.

6. **Does the physics help beyond a KAN? (attribution with a pre-specified endpoint).** In the released group means, PIKAN with alpha = beta = 1e-3 is close to the data-only KAN: XJTU b1-b6 MAPE 0.0037, 0.0126, 0.0077, 0.0068, 0.0100, 0.0062 vs KAN 0.0041, 0.0126, 0.0081, 0.0064, 0.0157, 0.0062 (`processed_results/.../PIKAN_opt_XJTU_results_group_mean.xlsx`, README 7.1), and the single-run 2-input comparison is 0.003580 vs 0.003724 MAPE (`PIKAN_XJTU_Var2.ipynb` cell 8 vs `KAN_XJTU_Var2.ipynb` cell 8). The repo has no controlled ablation. Test: factorial ablation (no physics / residual only / monotone-type term only / both), alpha and beta chosen by inner CV on training cells, multiple cell-level folds so the number of test cells is not 2-3.

7. **Loss-weight selection without a test-based grid.** PIKAN trains 49 (alpha, beta) pairs per seed and keeps the best on test MAPE; the gap between best and median group is 0.0031 vs 0.0042 (XJTU b1) and 0.0057 vs 0.0083 (HUST) for PIKAN, but 0.0060 vs 0.0242 (XJTU b1) and 0.0078 vs 0.0202 (HUST) for the PINN, so the method's practical value depends on sensitivity to the weights (`processed_results/results_soh-estimation/*group_mean.xlsx`, my summary). Test: adaptive weighting (self-adaptive residual weights, gradient-norm balancing, uncertainty weighting; kan-review 7.1 lists ssRBA) with weights fixed from training data only; endpoint: median-over-seeds performance and spread without any search, compared with the best-of-grid inner-CV choice.

8. **A dataset outside the four PINN4SOH tables.** Everything in both repos uses the same 16 charge-window features on XJTU, TJU, HUST, MIT (`PIKAN/README.md` section 4). Shlok's list names NASA PCoE and CALCE (raw curves, capacity regeneration in NASA, different protocols). Test: extract features from raw curves under a documented rule, run the best method from 5-7; endpoint: does the gain over a data-only KAN and over the PINN survive, and are the regeneration spikes captured? Required for the cycle-unit forecasting in gap 2 as well. Licence and cell counts to be checked by the data steward.

9. **Label-free handling of capacity regeneration.** PIKAN's physics term multiplies the predicted step by the true label step (`PIKAN_opt.py:190`), so it needs labels and rewards matching regeneration noise; PINN4SOH's paper states a different (pure monotone) form (paper Eq. 8). Test: compare (a) none, (b) pure non-increasing penalty with a learned slack for regeneration events, (c) the PIKAN term, on a dataset with real regeneration (NASA/CALCE), with endpoint error on the cycles around regeneration events and monotonicity violation rate on test cells.

10. **Identifiability of G from synthetic ground truth.** The PIKAN paper (abstract in README) claims that the discovered equation has "structural similarity to existing electrochemical models", yet the repo contains no synthetic experiment where the generating law is known (not found in the code I read; the paper itself may). Test: simulate cells from known laws (Verhulst, power-law, knee) with realistic noise, feed the PINN4SOH/PIKAN/our method, and measure recovery error of the law's parameters and of the functional form (e.g. after symbolic extraction). Cheap on CPU. Also tests the PINN4SOH degeneracy (G fed u_t, `Model.py:232`) by an ablation with and without u_t in G's input. A negative result (G not identifiable from SOH data of this kind) would itself be reportable.

Notes for the lead
- Items 1, 3, 4, 10 give the method novelty; 5-7 give the strong-baseline and attribution evidence a JES reviewer will ask for; 2, 8, 9 widen the scope (forecasting, new data, regeneration).
- PIKAN is in the target journal (JES 153, 120860, 2026-04) and its paper is unread; before committing to 1-4 the novelty auditor should confirm the paper does not already do them (the repo says it does not, but the paper may contain extra experiments not in the repo).

## 1. Research question and claim

**Question.** If battery capacity fade is written as a stress-conditioned rate law on a physics backbone, with the dependence of the rate on charge rate, discharge rate, depth of discharge (and temperature where measured) carried by a Kolmogorov-Arnold network, are the stress laws the network learns determined by the data (identifiable), and does the same model forecast the capacity trajectory and end of life of an unseen cell from its first few weeks of cycling?

**Single claim (falsifiable).** At the size and cadence of public ageing matrices (63 conditions, 4 replicate cells, weekly reference tests), a physics-backbone model whose stress dependence is a KAN (a) recovers the exponents and shapes of known stress laws on synthetic cells with the same design, (b) returns stable, rounding-robust stress laws across seeds, bootstrap resamples of cells and condition-held-out folds on the real cells, and (c) forecasts held-out cells at least as accurately as the best flexible data-driven baseline and more accurately than the semi-empirical, PiDDM-style and PIKAN-style baselines, whereas a PIKAN-style free-G model of identical capacity fails (a) and (b).

**What refutes it (stated now, fixed in the preregistration before confirmatory runs).**
- R1: synthetic recovery error of the three principal stress slopes at the ISU design is above the threshold (proposal: median relative error above 25 percent with the well-specified generator; the "pass" threshold of 10 percent is fixed after pilot P3 and before any real-data confirmatory run).
- R2: the free-G model recovers the stress laws as well as the structured model (paired difference not above the preregistered 2-fold margin).
- R3: the primary endpoint (section 6) of the proposed model is not better than the best of {semi-empirical, PiDDM-style, PIKAN-style, Wang-style} by a paired test, or is worse than the best flexible baseline (LightGBM / GP on stress plus early-window summary) by more than the preregistered non-inferiority margin.
- R4: a log-polynomial (GAM) stress map matches the KAN on every endpoint and is equally identifiable. Then the KAN is decoration; the paper's claim is rewritten without KAN superiority (the title would change; see section 2).
If R1 or R2 occurs the novelty-bearing part (C2) is dead and the topic must be re-opened; the remainder is the incremental C1 slice that the audit rates INCREMENTAL.

## 3. Method

### 3.1 State, coordinate, data per cell
- Cell c, rated stress vector s_c = (ln C_chg, ln C_dis, DoD), standardised with training-fold means and standard deviations only. For temperature datasets add u = 1/T (K^-1). ISU stress values per group are in the README (Table A1); the realised mean DoD is a measured property of each group.
- Capacity retention x(I~) = Q_RPT(I~)/Q_0,c where Q_0,c is the cell's own week-0 reference capacity (known at time zero). State y = 1 - x.
- **Time coordinate: equivalent full cycles I~ = cumulative discharged Ah / Q_0,c** (throughput). Rationale: groups differ by up to a factor of several in cycles per week, so a law in calendar weeks mixes cycle count and per-cycle damage. ISU gives weeks on test in `capacity_fade`; cycle counts need `Cycling_json` (10.2 GB, README section 4.1; per-cell file with per-cycle `capacity_discharge`). **Dependency D1** (needs the lead's yes; pilot P0 below fetches about 12 cells first). - Constant 30 C in ISU (README 3.2): the primary dataset has no Arrhenius test; temperature is treated in the secondary dataset (section 5).

### 3.2 Rate law (physics backbone)
Two loss mechanisms, y = y_1 + y_2, integrated in I~ from y(0) = 0:

- dy_1/dI~ = A_1 / (y_1 + y_0)  (self-limiting, SEI-type growth; sqrt(I~) law as y_0 �+' 0)
- dy_2/dI~ = A_2 A� exp(I3 y)  (throughput-driven loss that accelerates with accumulated damage: knee / plating / active-material-loss surrogate)
- ln A_i = f_i(s) + I'_{c,i} [+ Arrhenius term �^'(E_i/R)(1/T �^' 1/T_ref) where T is measured]

Global parameters (shared by all cells): y_0 > 0 (softplus), I3 �%� 0 (softplus), E_1, E_2 �%� 0 (secondary dataset), observation noise I� (retention units), prior scales I�_I',1 and I�_I',2. Per-cell parameters: I'_c = (I'_c1, I'_c2), two log-rate offsets (cell-to-cell variability). The stress dependence f_i(s) is the KAN (3.3). Only the offsets I'_c are per cell; nothing else is cell-specific, which is what makes the stress law global and testable.

Why this form. (i) It is a state-dependent rate law, not a curve fit: r(y, I~, s). (ii) Positivity and monotonicity hold **by architecture**: A_i = exp(A�) > 0, y_1 + y_0 > 0, so dy/dI~ > 0; no monotonicity penalty. (iii) of the 232 ISU cells with at least 10 reference points, 84 percent show a later-third mean fade rate above the first-third rate **[scratch, per week, not per I~]**, so an accelerating term is needed; a pure power law cannot represent it. (iv) Each term has a physical reading that reviewers recognise (diffusion-limited SEI growth; plating/knee feedback) without claiming mechanism identification, which is exactly what C2 tests.

**Backbone tournament, decided on training cells only (inner CV, tie goes to the simpler):** B1 power law y = A I~^z (state form); B2 sqrt + linear (I3 = 0); B3 the form above; B4 B3 with a free third term. The preregistered main model is the winner of the tournament on the training folds of the first confirmatory fold; the other backbones are reported in the ablation table. This guards against "chosen after seeing the test cells".

### 3.3 Where the KAN sits
Primary: **the KAN is the stress-to-log-rate map**, f: R^3 �+' R^2 (R^4 with 1/T), small: width [3, 2] (additive, a log-additive generalised additive model with learned univariate edges) or [3, h, 2] with h �^^ {2, 3} (interactions). **KAN variant.** B-spline KAN (pykan `MultKAN`, cubic splines, grid 4 to 8 with grid extension, SiLU base off or on by inner CV), for three reasons: PIKAN and PGKAN use B-spline KANs, so the contrast isolates how the KAN is used; pykan provides pruning and symbolic fitting with a user-defined library; B-splines allow local non-linearities such as a plating onset hinge. ### 3.6 Integrator and training
Vectorised RK4 over all cells in one batch on CPU, log-spaced I~ steps (400 steps; converge-check by halving, relative tolerance 1e-4; Dormand-Prince via torchdiffeq as a check if the package is available; **API and install status to verify**). Optimiser: Adam for 2,000 steps then L-BFGS refine, learning rate and weight decay tuned (nuisance); sparsity regularisation of the KAN edges (pykan-style L1 plus entropy, weights tuned by inner CV) so that pruning and symbolic fitting are meaningful (PIKAN used none, PIKAN.md section 2). ### 3.7 Per-cell parameters for an unseen cell from its first K weeks (causal)
Test-time: the cell's stress s_c and its early-window points (week 0 to W) are the only inputs. Estimate I'I,_c = argmax of the Gaussian likelihood of the window points under the integrated ODE plus the learned prior N(0, I�) (MAP, Gauss-Newton or L-BFGS, 2 unknowns, with 3 to 7 data points in the window [scratch: median number of points including t = 0 is 3, 5, 7 for W = 2, 4, 6 weeks]); then integrate forward. No quantity uses data after the window; Q_0 comes from week 0; scaling constants are global. The prior regularises the 2-dimensional problem; cells whose window has fewer than 2 points after t = 0 are excluded from that window's evaluation and counted. 
Train-test alignment: the first version fits I'_c on the full trajectory of training cells (a posteriori) and applies window-MAP at test; the **amortisation gap** is measured by an ablation in which training cells' I'_c are themselves obtained by window-MAP (unrolled five Gauss-Newton steps, differentiable). Whichever is better on inner CV is the main model.
Honest note: this is a nonlinear mixed-effects (hierarchical) formulation, standard outside batteries; the paper does not claim it as new, it claims the stress law and its identifiability.

### 3.8 Symbolic extraction
For the trained KAN (after sparsity-regularised training): (1) prune edges by attribution threshold chosen on training folds; (2) for each remaining univariate edge I+_ij(s_i) fit a symbolic form from a restricted library {aA�s + b, aA�sA� + bA�s + c, aA�ln(s)+b, aA�exp(b s)+c, power aA�s^p+b with p fitted, softplus/hinge max(0, s �^' s0) (onset)} with affine wrappers, via least squares on the edge's input-output samples; (3) choose per edge by an information criterion (not top RA� alone), with ties to the simpler form; (4) rounding: coefficients rounded to 2, 3 and 4 significant digits; the symbolic model is re-integrated and scored on training-fold validation cells. **Success criterion fixed in advance: forecast RMSE ratio (rounded symbolic / numeric KAN) �% 1.10 at 3 significant digits** (GAPS item 4), and formula length reported. Library is deliberately restricted; PIKAN's extended library (bessel, sinc, cosh) is not used because it produced fragile formulas (PIKAN.md section 6.6).

## 4. Identifiability programme

All of it is CPU-only and uses the real designs and noise, so it can run before anything is spent on real-data fits.

### 4.1 Synthetic cells from known laws
Generators (the ODE solved with a fine step, different from the training integrator, to avoid the inverse crime):
- **S1 well-specified:** the section-3.2 backbone with known log-additive stress laws (power-law exponents on C_chg, C_dis and DoD; with 1/T for the temperature design), per-cell offsets I'_c drawn from a Gaussian.
- **S2 hinge onset:** as S1 but ln A_2 has a threshold term max(0, ln C_chg �^' c0) (plating onset). Tests whether the KAN finds a shape that a quadratic GAM cannot (R4).

- **S4 free-G generator:** dy/dI~ drawn from a smooth random positive function of (y, I~, s) (Gaussian-process draw), to check that the free-G model can fit trajectories without having a unique law.

## 6. Experiments and endpoints (preregistrable)

**Common forecasting task, identical for every model.** Input: s_c, Q_0,c, the reference points in the first W weeks (the "window"); output: retention at every reference test after the window. Every model, physical or not, gets the same inputs and the same permission to adapt to the cell from its window (a per-cell scale for the semi-empirical model, the I'_c MAP for ours, the window summary as static input for learned baselines).
- **Windows:** W �^^ {2, 4, 6} weeks; **primary W = 4** (5 points including t = 0 at the median; about a third of the median life). Cells whose life ends inside the window are excluded and counted (5.2 percent of cells have time to 80 percent �% 4 weeks, 2.4 percent �% 2 weeks [scratch]).
- **Forecast set F_c:** reference tests after the window up to the first test below 70 percent retention (so the 80 percent end of life and the knee are inside).
- **Primary endpoint (one):** cell-level RMSE of retention (percentage points) over F_c, macro-averaged over test conditions, **Test B, W = 4**, final frozen configuration, 5 seeds.
- **Secondary:** (S1) the same on Test A and Test C; (S2) end-of-life error |ln(I~I,_80/I~_80)| and the share within A�20 percent (and weeks if F1); (S3) remaining-useful-life error at +2, +4, +8 weeks after the window; (S4) MAE, MAPE (retention in percent) and RA� for completeness, with the correct metric argument order (PIKAN.md section 6.7); (S5) forecast error versus W �^^ {2, 4, 6}; (S6) identifiability endpoints I1 to I3 below; (S7) SNL equivalents; (S8) wall-clock and parameter count.
- **Identifiability endpoints.** I1: median relative error of the three principal stress slopes on S1 at the ISU design (pass threshold fixed after P3); I2: seed, bootstrap and fold CV of the slopes on real cells and their ranking agreement (Kendall W); I3: rounding ratio �% 1.10 at 3 significant digits on real validation cells; each compared with the free-G model by a paired test over synthetic draws.
- **Tuning (all models, same rules).** Inner grouped CV on training cells only: by condition for Test B and C, by cell for Test A. ## 1. Research question and claim

**Question.** If battery capacity fade is written as a stress-conditioned rate law on a physics backbone, with the dependence of the rate on charge rate, discharge rate, depth of discharge (and temperature where measured) carried by a Kolmogorov-Arnold network, are the stress laws the network learns determined by the data (identifiable), and does the same model forecast the capacity trajectory and end of life of an unseen cell from its first few weeks of cycling?

**Single claim (falsifiable).** At the size and cadence of public ageing matrices (63 conditions, 4 replicate cells, weekly reference tests), a physics-backbone model whose stress dependence is a KAN (a) recovers the exponents and shapes of known stress laws on synthetic cells with the same design, (b) returns stable, rounding-robust stress laws across seeds, bootstrap resamples of cells and condition-held-out folds on the real cells, and (c) forecasts held-out cells at least as accurately as the best flexible data-driven baseline and more accurately than the semi-empirical, PiDDM-style and PIKAN-style baselines, whereas a PIKAN-style free-G model of identical capacity fails (a) and (b).

## 3. Method

### 3.1 State, coordinate, data per cell

- Capacity retention x(I~) = Q_RPT(I~)/Q_0,c where Q_0,c is the cell's own week-0 reference capacity (known at time zero). State y = 1 - x.
- **Time coordinate: equivalent full cycles I~ = cumulative discharged Ah / Q_0,c** (throughput). ### 3.2 Rate law (physics backbone)
Two loss mechanisms, y = y_1 + y_2, integrated in I~ from y(0) = 0:

- dy_1/dI~ = A_1 / (y_1 + y_0)  (self-limiting, SEI-type growth; sqrt(I~) law as y_0 �+' 0)
- dy_2/dI~ = A_2 A� exp(I3 y)  (throughput-driven loss that accelerates with accumulated damage: knee / plating / active-material-loss surrogate)
- ln A_i = f_i(s) + I'_{c,i} [+ Arrhenius term �^'(E_i/R)(1/T �^' 1/T_ref) where T is measured]

Per-cell parameters: I'_c = (I'_c1, I'_c2), two log-rate offsets (cell-to-cell variability). The stress dependence f_i(s) is the KAN (3.3). Only the offsets I'_c are per cell; nothing else is cell-specific, which is what makes the stress law global and testable.

Why this form. (i) It is a state-dependent rate law, not a curve fit: r(y, I~, s). (ii) Positivity and monotonicity hold **by architecture**: A_i = exp(A�) > 0, y_1 + y_0 > 0, so dy/dI~ > 0; no monotonicity penalty. (iii) of the 232 ISU cells with at least 10 reference points, 84 percent show a later-third mean fade rate above the first-third rate **[scratch, per week, not per I~]**, so an accelerating term is needed; a pure power law cannot represent it. (iv) Each term has a physical reading that reviewers recognise (diffusion-limited SEI growth; plating/knee feedback) without claiming mechanism identification, which is exactly what C2 tests.

**Backbone tournament, decided on training cells only (inner CV, tie goes to the simpler):** B1 power law y = A I~^z (state form); B2 sqrt + linear (I3 = 0); B3 the form above; B4 B3 with a free third term. The preregistered main model is the winner of the tournament on the training folds of the first confirmatory fold; the other backbones are reported in the ablation table. ### 3.6 Integrator and training

### 3.7 Per-cell parameters for an unseen cell from its first K weeks (causal)
Test-time: the cell's stress s_c and its early-window points (week 0 to W) are the only inputs. Estimate I'I,_c = argmax of the Gaussian likelihood of the window points under the integrated ODE plus the learned prior N(0, I�) (MAP, Gauss-Newton or L-BFGS, 2 unknowns, with 3 to 7 data points in the window [scratch: median number of points including t = 0 is 3, 5, 7 for W = 2, 4, 6 weeks]); then integrate forward. No quantity uses data after the window; Q_0 comes from week 0; scaling constants are global. The prior regularises the 2-dimensional problem; cells whose window has fewer than 2 points after t = 0 are excluded from that window's evaluation and counted. 
Train-test alignment: the first version fits I'_c on the full trajectory of training cells (a posteriori) and applies window-MAP at test; the **amortisation gap** is measured by an ablation in which training cells' I'_c are themselves obtained by window-MAP (unrolled five Gauss-Newton steps, differentiable). Whichever is better on inner CV is the main model.
Honest note: this is a nonlinear mixed-effects (hierarchical) formulation, standard outside batteries; the paper does not claim it as new, it claims the stress law and its identifiability.

### 3.8 Symbolic extraction
For the trained KAN (after sparsity-regularised training): (1) prune edges by attribution threshold chosen on training folds; (2) for each remaining univariate edge I+_ij(s_i) fit a symbolic form from a restricted library {aA�s + b, aA�sA� + bA�s + c, aA�ln(s)+b, aA�exp(b s)+c, power aA�s^p+b with p fitted, softplus/hinge max(0, s �^' s0) (onset)} with affine wrappers, via least squares on the edge's input-output samples; (3) choose per edge by an information criterion (not top RA� alone), with ties to the simpler form; (4) rounding: coefficients rounded to 2, 3 and 4 significant digits; the symbolic model is re-integrated and scored on training-fold validation cells. **Success criterion fixed in advance: forecast RMSE ratio (rounded symbolic / numeric KAN) �% 1.10 at 3 significant digits** (GAPS item 4), and formula length reported. Library is deliberately restricted; PIKAN's extended library (bessel, sinc, cosh) is not used because it produced fragile formulas (PIKAN.md section 6.6).

## 4. Identifiability programme

All of it is CPU-only and uses the real designs and noise, so it can run before anything is spent on real-data fits.

### 4.1 Synthetic cells from known laws
Generators (the ODE solved with a fine step, different from the training integrator, to avoid the inverse crime):
- **S1 well-specified:** the section-3.2 backbone with known log-additive stress laws (power-law exponents on C_chg, C_dis and DoD; with 1/T for the temperature design), per-cell offsets I'_c drawn from a Gaussian.
- **S2 hinge onset:** as S1 but ln A_2 has a threshold term max(0, ln C_chg �^' c0) (plating onset). Tests whether the KAN finds a shape that a quadratic GAM cannot (R4).
- **S3 misspecified:** generator with a different knee mechanism (logistic accelerating term, or a Bacon-Watts two-regime power law) so the fit model is wrong; measures how recovery degrades and whether the stress ordering survives.

## 6. Experiments and endpoints (preregistrable)

**Common forecasting task, identical for every model.** Input: s_c, Q_0,c, the reference points in the first W weeks (the "window"); output: retention at every reference test after the window. ## 1. Verdict: revise; do not commit to the proposal as written

The identifiable-law question is the strongest novelty slice, but the proposal bundles too many hard problems for one week: a new two-mechanism ODE, hierarchical estimation, forecasting, KAN symbolic extraction, free-\(G\) and strict-PINN controls, synthetic recovery studies, several splits, and multiple datasets. That is a project plan, not a one-week paper plan.

There is also a modeling risk before the ML begins. The proposed \(y_2\) term accelerates exponentially with accumulated damage; the author must show that it stays well behaved over the forecast horizon and does not simply create a fitted knee. The two-mechanism interpretation is a modeling assumption, not evidence that those mechanisms were separately measured or identified. The proposal’s own concern that only about three post-baseline points are available in the median four-week window makes per-cell estimation of two offsets questionable. **Unverified:** the stated point counts and preliminary recovery thresholds depend on scratch analyses, not reproduced confirmatory runs.

A JES editor could say: “This is close to recent PINN/KAN degradation papers; what is the distinct contribution?” Reviewer 1 could say: “You call the laws identifiable, but the result is conditional on your chosen ODE and KAN class. Why do stable coefficients establish physical identifiability?” Reviewer 2 could say: “The model has many choices and baselines; show me a leakage-proof, held-out-condition experiment and a fair GAM comparison. Also, why use this two-term law?” The full text and methods of several cited papers remain unread per the proposal, so novelty is not yet secure.

**Revision:** make the paper a focused test of *when a stress law is recoverable from a designed ageing matrix*. Keep forecast performance as a validation endpoint. Drop the claim that the KAN has discovered mechanisms. Start with one fixed, defensible rate-law family and one dataset; only add the second dataset after the pilot works.

## 2. Must a genuine PINN be central?

A hard-constrained ODE with a KAN stress map is a reasonable **physics-informed model**, but it is not a strict PINN. If “PINN + KAN” must be the headline, a solution-network PINN can be built:

- **Solution network:** \(y_\theta(\tilde I,s,\eta_c)\), with \(y_\theta(0)=0\) imposed by construction. The KAN maps stress to positive rate parameters; \(\eta_c\) are cell offsets estimated from the early window.
- **Residual:** at collocation points, penalize \(dy_\theta/d\tilde I-R(y_\theta,\tilde I,s;\eta_c)\). Place points along training-cell trajectories, including beyond the observed early window into the forecast interval. Fit data only at observed reference-test points; never collocate on or tune against held-out future labels.
- **What it adds:** it can regularize a smooth solution between sparse observations and constrain the forecast region using a specified ODE. It cannot create evidence for the ODE beyond the window. If the same rate law is already integrated exactly, the hard ODE model enforces that constraint more directly and with fewer optimization choices.

So I would **not** make the PINN central by default. Run it as a controlled comparison against the integrated ODE model. A soft residual does real work only if the learned solution differs meaningfully from numerical integration and the difference improves a preregistered held-out forecast without sacrificing law recovery. Otherwise, call the method physics-informed KAN, not PINN. CPU feasibility is plausible for a small network, but the proposal’s training plan and compute time are **unverified**; pilot that before promising a PINN result.

## 3. Dataset choice

For identifiability, designed variation and replication matter more than cell count alone. ISU-ILCC’s stated 63 conditions with replicates is attractive, but weekly sampling and small pouch cells limit the resolution of a continuous-time rate law. The author also says cycle counts require a large `Cycling_json` download; if equivalent full cycles cannot be computed promptly and reliably, the proposed throughput coordinate is a blocker.

Samsung INR21700-50E appears more compelling for JES appeal if its stated 279 cells and 71 temperature/DoD/C-rate conditions are confirmed. Its 10.3 GB size and parse/runtime costs make it a risky one-week choice. **Unverified:** the available files, condition replication, and actual completeness of the release. Sandia is appealing for chemistry and stress breadth, but its usable replication structure and processed data status are also **unverified**.

**My choice:** ISU primary only if the overnight data pilot confirms usable cycling exposure, per-condition replication, and enough post-window observations. Otherwise use Samsung only if it is already accessible and a small, nonselective data audit shows a viable design. Do not quietly substitute a convenient subset. Add Sandia as secondary only if it can be processed without consuming the core analysis time; do not make an Arrhenius claim from a dataset whose temperature metadata and coverage have not been checked.

## 4. Can KAN beat a GAM or polynomial?

Potentially, if the stress-to-rate relationship has a localized onset or interaction—for example, a charge-rate threshold whose effect changes with DoD. That is a hypothesis, not an established advantage here. With only three or four stress inputs and a designed condition matrix, an additive spline GAM may be more stable, simpler, and easier to interpret.

Use identical splits and inputs, training-only scaling, comparable effective degrees of freedom, and equal tuning effort. Compare KAN against a degree-2 log-polynomial, additive spline GAM, and a GAM with prespecified interactions. Evaluate held-out conditions, not only held-out replicate cells; plot the learned map and uncertainty across stress-space coverage. If KAN does not improve held-out prediction or law recovery, report that plainly and remove KAN superiority from the claim.

## 5. Title, claim, and figures

**Title I would bet on:** *When Are Stress-Dependent Battery Degradation Laws Identifiable from Ageing Data?*

It avoids promising that KAN is superior or that learned expressions are electrochemical mechanisms. The claim should be conditional: under specified model classes and tested stress designs, quantify whether law parameters and predictive stress-response shapes can be recovered and remain stable under resampling.

A compelling paper needs four main figures:

1. Dataset condition map, replicate fade curves, and observed noise/resolution.
2. Synthetic recovery plot across the actual design and degraded designs, with structured and free-\(G\) models.
3. Held-out-condition forecast curves with the observed fitting window marked, alongside the strongest simple and flexible baselines.
4. Law stability: seed/fold/bootstrap envelopes and rounded symbolic law predictions against the numerical KAN, including regions where the design provides little support.

Those figures matter more than a long architecture schematic or a leaderboard table.

## 6. Biggest risk and tonight’s cheapest pilot

**Biggest risk:** the identifiability headline may be circular or untestable in the real data. A structured model can recover parameters from synthetic data generated by the same structure, while real-data coefficient instability may reflect model misspecification and sparse sampling rather than a meaningful failure of identifiability. Stable predictions can also coexist with unstable equations.

**Kill/confirm pilot tonight:** take a small, spread of conditions from the primary dataset; verify the per-cell time coordinate and observation cadence; fit the simplest proposed rate model and a log-polynomial/GAM using grouped condition holdouts. In parallel, generate synthetic data at that exact design with known stress slopes and realistic replicate noise, then recover the slopes across resamples. If the simpler model fits at the measurement-noise level, or slopes are not recoverable under the real design, stop the KAN-identifiability claim before building the larger model.

The identifiable-law question is the strongest novelty slice, but the proposal bundles too many hard problems for one week: a new two-mechanism ODE, hierarchical estimation, forecasting, KAN symbolic extraction, free-\(G\) and strict-PINN controls, synthetic recovery studies, several splits, and multiple datasets. That is a project plan, not a one-week paper plan.

There is also a modeling risk before the ML begins. The proposed \(y_2\) term accelerates exponentially with accumulated damage; the author must show that it stays well behaved over the forecast horizon and does not simply create a fitted knee. The two-mechanism interpretation is a modeling assumption, not evidence that those mechanisms were separately measured or identified. The proposal’s own concern that only about three post-baseline points are available in the median four-week window makes per-cell estimation of two offsets questionable. **Unverified:** the stated point counts and preliminary recovery thresholds depend on scratch analyses, not reproduced confirmatory runs.

A JES editor could say: “This is close to recent PINN/KAN degradation papers; what is the distinct contribution?” Reviewer 1 could say: “You call the laws identifiable, but the result is conditional on your chosen ODE and KAN class. Why do stable coefficients establish physical identifiability?” Reviewer 2 could say: “The model has many choices and baselines; show me a leakage-proof, held-out-condition experiment and a fair GAM comparison. Also, why use this two-term law?” The full text and methods of several cited papers remain unread per the proposal, so novelty is not yet secure.

**Revision:** make the paper a focused test of *when a stress law is recoverable from a designed ageing matrix*. Keep forecast performance as a validation endpoint. Drop the claim that the KAN has discovered mechanisms. Start with one fixed, defensible rate-law family and one dataset; only add the second dataset after the pilot works.

## 2. Must a genuine PINN be central?

A hard-constrained ODE with a KAN stress map is a reasonable **physics-informed model**, but it is not a strict PINN. If “PINN + KAN” must be the headline, a solution-network PINN can be built:

- **Solution network:** \(y_\theta(\tilde I,s,\eta_c)\), with \(y_\theta(0)=0\) imposed by construction. The KAN maps stress to positive rate parameters; \(\eta_c\) are cell offsets estimated from the early window.
- **Residual:** at collocation points, penalize \(dy_\theta/d\tilde I-R(y_\theta,\tilde I,s;\eta_c)\). Place points along training-cell trajectories, including beyond the observed early window into the forecast interval. Fit data only at observed reference-test points; never collocate on or tune against held-out future labels.
- **What it adds:** it can regularize a smooth solution between sparse observations and constrain the forecast region using a specified ODE. It cannot create evidence for the ODE beyond the window. If the same rate law is already integrated exactly, the hard ODE model enforces that constraint more directly and with fewer optimization choices.

So I would **not** make the PINN central by default. Run it as a controlled comparison against the integrated ODE model. A soft residual does real work only if the learned solution differs meaningfully from numerical integration and the difference improves a preregistered held-out forecast without sacrificing law recovery. Otherwise, call the method physics-informed KAN, not PINN. CPU feasibility is plausible for a small network, but the proposal’s training plan and compute time are **unverified**; pilot that before promising a PINN result.

## 3. Dataset choice

For identifiability, designed variation and replication matter more than cell count alone. ISU-ILCC’s stated 63 conditions with replicates is attractive, but weekly sampling and small pouch cells limit the resolution of a continuous-time rate law. The author also says cycle counts require a large `Cycling_json` download; if equivalent full cycles cannot be computed promptly and reliably, the proposed throughput coordinate is a blocker.

Samsung INR21700-50E appears more compelling for JES appeal if its stated 279 cells and 71 temperature/DoD/C-rate conditions are confirmed. Its 10.3 GB size and parse/runtime costs make it a risky one-week choice. **Unverified:** the available files, condition replication, and actual completeness of the release. Sandia is appealing for chemistry and stress breadth, but its usable replication structure and processed data status are also **unverified**.

**My choice:** ISU primary only if the overnight data pilot confirms usable cycling exposure, per-condition replication, and enough post-window observations. Otherwise use Samsung only if it is already accessible and a small, nonselective data audit shows a viable design. Do not quietly substitute a convenient subset. Add Sandia as secondary only if it can be processed without consuming the core analysis time; do not make an Arrhenius claim from a dataset whose temperature metadata and coverage have not been checked.

## 4. Can KAN beat a GAM or polynomial?

Potentially, if the stress-to-rate relationship has a localized onset or interaction—for example, a charge-rate threshold whose effect changes with DoD. That is a hypothesis, not an established advantage here. With only three or four stress inputs and a designed condition matrix, an additive spline GAM may be more stable, simpler, and easier to interpret.

Use identical splits and inputs, training-only scaling, comparable effective degrees of freedom, and equal tuning effort. Compare KAN against a degree-2 log-polynomial, additive spline GAM, and a GAM with prespecified interactions. Evaluate held-out conditions, not only held-out replicate cells; plot the learned map and uncertainty across stress-space coverage. If KAN does not improve held-out prediction or law recovery, report that plainly and remove KAN superiority from the claim.

## 5. Title, claim, and figures

**Title I would bet on:** *When Are Stress-Dependent Battery Degradation Laws Identifiable from Ageing Data?*

It avoids promising that KAN is superior or that learned expressions are electrochemical mechanisms. The claim should be conditional: under specified model classes and tested stress designs, quantify whether law parameters and predictive stress-response shapes can be recovered and remain stable under resampling.

A compelling paper needs four main figures:

1. Dataset condition map, replicate fade curves, and observed noise/resolution.
2. Synthetic recovery plot across the actual design and degraded designs, with structured and free-\(G\) models.
3. Held-out-condition forecast curves with the observed fitting window marked, alongside the strongest simple and flexible baselines.
4. Law stability: seed/fold/bootstrap envelopes and rounded symbolic law predictions against the numerical KAN, including regions where the design provides little support.

Those figures matter more than a long architecture schematic or a leaderboard table.

## 6. Biggest risk and tonight’s cheapest pilot

**Biggest risk:** the identifiability headline may be circular or untestable in the real data. A structured model can recover parameters from synthetic data generated by the same structure, while real-data coefficient instability may reflect model misspecification and sparse sampling rather than a meaningful failure of identifiability. Stable predictions can also coexist with unstable equations.

**Kill/confirm pilot tonight:** take a small, spread of conditions from the primary dataset; verify the per-cell time coordinate and observation cadence; fit the simplest proposed rate model and a log-polynomial/GAM using grouped condition holdouts. In parallel, generate synthetic data at that exact design with known stress slopes and realistic replicate noise, then recover the slopes across resamples. If the simpler model fits at the measurement-noise level, or slopes are not recoverable under the real design, stop the KAN-identifiability claim before building the larger model.
