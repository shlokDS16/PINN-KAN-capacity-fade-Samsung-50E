## 1. The model as equations
Names: the repo calls the solution network `solution_u` (F in the notebooks' plot labels, `F(.)`), the dynamics network `dynamical_F` (G in the notebooks, `G(.)`). Same as Wang et al. (Nat. Commun. 2024) F and G.

- **Inputs.** One row per (cell, cycle k): 16 charge-segment health indicators x_k plus a 17th column "cycle index" t_k. After per-cell min-max scaling both lie in [-1, 1] (see section 3). Label y_k = SOH = capacity / nominal capacity.
- **Solution network** (`Model/PIKAN_opt.py:11-23,74`): u_k = F(x_k, t_k) = KAN_pred(KAN_enc([x_k, t_k])), encoder widths 17-60-60-32 and predictor 32-32-1 (efficient-kan, `:14-15`). Output is SOH.
- **Dynamics network** (`:75`): G = KAN [34, 60, 60, 1]. Input is the concatenation [x_k, t_k, u_k, u_x] (16 + 1 + 1 + 16 = 34; comment at `:75` says it is deliberately not 35, "does not include the partial derivative of u with respect to t"); `:167`.
- **Autograd derivatives** (`:152-165`): u_t = dF/dt at fixed x_k, u_x = dF/dx (16-vector), both with `create_graph=True`.
- **Residual actually implemented** (`:167-169`):
  f(x_k, t_k) = u_t(x_k, t_k) - G(x_k, t_k, u_k, u_x(x_k, t_k)).
- **Loss** (`:183-193`), with a pair (k, k+1) of consecutive stored cycles of one cell as one sample:
  - L_data = 0.5 MSE(u_k, y_k) + 0.5 MSE(u_{k+1}, y_{k+1})  (`:183`)
  - L_PDE = 0.5 MSE(f_k, 0) + 0.5 MSE(f_{k+1}, 0)  (`:186-187`)
  - L_phys = sum over the batch of ReLU[ (u_{k+1} - u_k) (y_k - y_{k+1}) ]  (`:190`; a **sum**, not a mean, so its weight scales with batch size 256/512)
  - L = L_data + alpha L_PDE + beta L_phys  (`:193`)
- **Weights.** Default alpha = 0.7, beta = 0.2 (`main_our_models_optimize_XJTU.py:248-249`) but **never used as defaults in the reported runs**: every reported run searches the 7 x 7 grid {1e-3, 1e-2, 1e-1, 1, 10, 100, 1e3} for both (`:250-251`, loops at `:121-122`) — see section 6.
- **Constraint semantics.** L_phys is not the monotonicity penalty of the PINN4SOH paper (ReLU(u_{k+1} - u_k)). It multiplies the predicted difference by the **true** label difference, so it penalises "predicted step has the opposite sign to the true step", in both directions: it penalises a predicted decline when the label rises (capacity regeneration) as well as a predicted rise when the label falls. It therefore uses test-time-unavailable information (label differences) and encourages the network to reproduce label noise and regeneration spikes in training. It is not a monotonicity constraint on the model (inference of mine from `:190`; the code comment says "considering capacity regeneration").
- **Difference from PINN4SOH.** PINN4SOH feeds u_t into G as well (35 inputs; `refs/code/_dl_PINN4SOH/raw/Model/Model.py:232`), which makes the PDE residual trivially solvable by G = identity on u_t. PIKAN removes u_t from G's input, so its residual is not trivially zero. This is a real fix, credit it, and it is where the PIKAN "physics" first differs.

**Symbolic extraction or interpretation: YES, but only in the notebooks on 2-input models, never in the main experiments.** Flow (XJTU, batch 1, `PIKAN_XJTU_Var2.ipynb`): train pykan F[2,4,1], G[4,2,1] with the PIKAN loss → `prune()` (cells 11, 13) → retrain → `auto_symbolic()` (cells 20-21) with an extended library (bessel_j0, erf, sinc, softmax, sigmoid, relu, cosh, sinh, arcsinh, arccosh; cell 19) → `symbolic_formula()` (cells 25-26). Prior-guided variant (`*_PDEAutoDiscovery.ipynb`): G is given only u as input, the top suggested function is chosen by hand (`fix_symbolic(0,0,0,'x')`, `fix_symbolic(1,0,0,'x^2')`, cell 23) and the resulting parabola is re-expressed as a Verhulst (logistic) law, markdown cell 29: du/dt = r(u-C)(1-(u-C)/(K-C)) with a = coefficient, giving r, C, K in cell 30.

## 3. Data
- **Datasets** (README section 4, `Data/`): XJTU (55 cells, 6 batches/protocols, NCM), TJU (130 cell files in 3 batches NCA / NCM / NCM+NCA), MIT/Severson (125 files, 3 batches, LFP), HUST (77 files, LFP). I.e. the four PINN4SOH feature tables; no other dataset is used anywhere in the repo.
- **Feature files:** per-cell CSVs with 16 columns + `capacity` (header in every file, checked): voltage mean, std, kurtosis, skewness, CC Q, CC charge time, voltage slope, voltage entropy, current mean, std, kurtosis, skewness, CV Q, CV charge time, current slope, current entropy. These are the Wang et al. features: statistics of voltage in [V_end - 0.2 V, V_end] and of CV-stage current from 0.5 A to 0.1 A (Wang et al. 2024, Methods "Feature extraction"). The 17th input is "cycle index".
- **Label:** SOH = capacity / nominal capacity with nominal 2.0 (XJTU), 1.1 (HUST, MIT), [3.5, 3.5, 2.5] (TJU batches) (`dataloader.py:57,191-194,268-270,316-318`).
- **Normalisation (`dataloader.py:44-67`, called per file):** `df.insert(..., 'cycle index', arange(n))` at `:51`, 3-sigma row deletion `:53`, then **per cell** min-max `2*(f-min)/(max-min)-1` over **all 17 input columns including cycle index, using that cell's own whole-life min and max** (`:58-65`; default `--normalization_method min-max` in every main script, e.g. `main_our_models_optimize_XJTU.py:232`). The XJTU_Dataloader notebook output (cell 5) prints the normalised cycle index running linearly from -1.000 to +1.000 over 371 cycles. Hence **t_k = -1 + 2k/(N-1) = fraction of the cell's total life**, and every test cell is scaled by its own end-of-life cycle count and its own whole-life feature ranges. (The dataloader's own `__main__` default is z-score, `:359`, not used by the scripts.)
- **3-sigma filter (`:18-42`):** drops any row where **any** column, including `capacity` (the label), lies beyond mean ± 3 sd of that cell. Applied to test cells too, so the scored cycle set is chosen with test labels, and "consecutive" pairs (k, k+1) may skip deleted cycles.
- **Train / test cells (cell-level split, hard-coded):**
  - XJTU (`main_our_models_optimize_XJTU.py:18-24`): within one batch, any file name containing the character '4' or '8' is test, all else train. For 2C, R2.5, R3, RW, satellite that is cells 4 and 8 (2 test, 6 train); for 3C it also catches `3C_battery-14`, giving 3 test cells (12 train). Train and test are the same protocol (same batch). Test set per batch is 2-3 cells.
  - HUST (`main_our_models_optimize_HUST.py:13-17`): 20 listed ids are test, the remaining 57 train.
  - MIT (`main_our_models_optimize_MIT.py:20-25`): per batch, cell id divisible by 5 is test.
  - TJU (`main_our_models_optimize_TJU.py:13-33`): units digit 5/9 (batches 1, 3) or 4/8 (batch 2) of the file order index (OS directory order) is test, within batch.
  - small sample (`train_list[:small_sample]`, n = 1..4): first n files of an unsorted `os.listdir`, i.e. an OS-dependent and unreported choice of cells.
- **Can test-cell data reach training, tuning or early stopping?**
  1. Training/validation: both come from **training cells only**; the validation set is a **random 20 % of consecutive-cycle pairs** of the training cells (`dataloader.py:158-159`, `random_state=420`), so validation pairs are neighbours of training pairs from the same cell. Early stopping and checkpoint choice use this near-duplicate validation MSE (`PIKAN_opt.py:224-228,243`), not test. Test cells do not enter training.
  2. **Hyper-parameter selection uses the test set** (confirmed, `main_our_models_optimize_XJTU.py:121-145`): for each seed, 49 (alpha, beta) pairs are trained and the pair with the lowest **test MAPE** is kept (`if metrics[1] < best_MAPE`, `:138`); its test predictions, parameters and hyper-parameters are saved as `best_results`, and the README tables are the mean of those (aggregation `results_analysis_code/Model_optimize_XJTU_results.py:31` reads `best_results`). The same pattern is in the HUST, MIT, TJU scripts. Authors also released per-group means over all 49 pairs (`*_group_mean.xlsx`), see section 5.
  3. Per-cell normalisation, 3-sigma filtering and the t-feature (above) use whole-life information of each test cell.
  4. Transfer: the per-target fine-tuning learning rates are hard-coded per pair without any stated selection rule (`main_our_models_fine_tuning.py:244,257`; the fine-tuning early-stop patience is 10, `:315`), selection method unknown.

## 4. Training
- Optimiser: Adam for F with the schedule 30 warm-up epochs from 2e-3 to 1e-2 then cosine to 2e-4 over the remaining epochs of 200 (`Model/PIKAN_opt.py:31-57,78,81-86`; defaults `main_...XJTU.py:235-241`); Adam for G with constant lr_F = 1e-3 (`:79`; XJTU, `:241`; fine-tuning uses 1e-2, `main_our_models_fine_tuning.py:320`). Because early stopping (patience 20 on validation MSE, `:243`) will usually stop before epoch 200, the cosine tail may rarely be reached (not checked per run).
- Batch size 256 (XJTU), 512 (HUST, MIT, TJU), 128 for small-sample (`main_our_models_optimize_XJTU.py:231,168`). Epoch = full pass over training pairs. No gradient clipping.
- Early stopping criterion: validation MSE of F on the random-pair validation split (`:135-148,224-246`); the test set is also evaluated each time validation improves, only for logging and for saving the test predictions (`:228-234`).
- Seeds: `set_seed(e)` for e = 0..9 → 10 seeds (`main_...XJTU.py:111-112`); `utils/util.py:21-35` also sets cudnn deterministic. Interpretability notebooks use seed 25 (single run). README gives means only, no standard deviation; the released xlsx contain per-seed rows so a spread can be recomputed.
- Baselines (`main_comparision_*.py`): MLP, CNN, KAN (same 17-60-60-32-32-1), KAN-medium, Transformer, trained once per seed, **single configuration, no (alpha, beta)-type search, early-stopping patience 10 vs 20 for PIKAN/PINN** (`main_comparision_XJTU.py:103`; PIKAN `--early_stop` default 20, `main_our_models_optimize_XJTU.py:236`). The PINN baseline is the same 49-point test-selected search as PIKAN (`Model/PINN_opt.py`, run through `main_our_models_optimize_*`).

## 6. Hidden assumptions, bugs and weaknesses (concrete)
1. **Test-set hyper-parameter selection.** Best of 49 (alpha, beta) per seed by test MAPE (`main_our_models_optimize_XJTU.py:121-145`, the other three datasets likewise). The authors' own `group_mean` workbooks (`processed_results/results_soh-estimation/PIKAN_opt/PIKAN_opt_*_results_group_mean.xlsx`, columns idx / MAE / MAPE / RMSE, my summary with a stdlib xlsx reader, all means over 10 seeds): for the best README row 0.0031 (XJTU b1) the median group is 0.0042 and the mean 0.0049; XJTU b2 best 0.0089, median 0.0125; HUST best 0.0057, median 0.0083; TJU b1 0.0088 vs median 0.0106. For the PINN baseline the gap is far larger (XJTU b1 best 0.0060, median 0.0242; HUST best 0.0078, median 0.0202). Best-of-grid is selected on the test cells, so the published row is optimistic by an unknown amount; the group medians show PIKAN is far less sensitive to (alpha, beta) than the sine-MLP PINN.
2. **Physics terms add little.** With alpha = beta = 1e-3 (group 1; essentially no physics) PIKAN's mean test MAPE is 0.0037, 0.0126, 0.0077, 0.0068, 0.0100, 0.0062 on XJTU b1-6, 0.0065 HUST, 0.0061 MIT, 0.0102 / 0.0136 / 0.0058 TJU b1-3, versus the data-only KAN row of the README (0.0041, 0.0126, 0.0081, 0.0064, 0.0157, 0.0062; HUST 0.0064; MIT 0.0060). The "best group" per batch picks alpha/beta all over the grid (e.g. XJTU b1 alpha = 0.01 beta = 0.1; b2 alpha = 100 beta = 10; b3 alpha = 0.001 beta = 0.1) with no consistent pattern. Together with the single-run KAN vs PIKAN comparison in section 5 this suggests most of the gain over PINN comes from replacing a sine-MLP by a KAN (and 10x more parameters), not from the physics; the repo contains no controlled ablation for it (the paper may; not read).
3. **The "PDE" residual is not a battery physics law.** G is a free network trained by the same optimiser; the residual forces F's ∂/∂t at fixed features to agree with G's output. Nothing ties G to an observed ∂SOH/∂cycle. The cell's SOH changes with k both through t and through the drifting features x_k, so the physically meaningful rate is the total derivative u_t + u_x . dx/dk, not u_t alone at fixed x. The pair (x_k, x_{k+1}) is available in the data loader but is not used to build a total-derivative residual (inference from `PIKAN_opt.py:152-170`, `dataloader.py:77-83`).
4. **Time variable is life fraction, not cycles.** Per-cell min-max (`dataloader.py:58-65`; notebook cell 5 output) makes t = -1 + 2k/(N-1). Consequences: (a) the model needs each test cell's end-of-life cycle count N (and whole-life feature ranges) to scale its inputs, i.e. estimation is not causal/online; (b) ∂u/∂t and the discovered G are rates per unit **normalised life**, so a cell that lives twice as long has half the rate; "dynamics shared across cells/batteries" and "cross-battery transferability" of an equation are then comparing rates in different time units; (c) a 2-input model [one HI, t] already reaches MAPE 0.36 % on XJTU b1, which says life fraction alone carries much of the signal; the repo has no t-only baseline. (I treat (c) as a control we must run in our own work, not as our contribution.)
5. **The discovered "degradation laws" are not stable across datasets.** Prior-guided G(u), fitted per dataset (`*_PDEAutoDiscovery.ipynb` cell 28): XJTU 0.3067 (u + 0.6144)^2 - 0.7876; HUST 0.5289 (0.0146 - u)^2 - 0.6422; MIT 9.9945 (u - 0.9476)^2 - 0.0092; TJU 0.4035 (0.2592 u - 1)^2 - 0.3959. The Verhulst parameters computed for XJTU (cell 30) are r = -0.983, C = -2.217, K = 0.988: a lower asymptote C = -2.2 is not a physical SOH asymptote. Curvature, vertex and sign differ strongly between datasets (and the MIT curvature is 30 times the XJTU one). The README's "structural similarity to existing electrochemical models" is a claim about a parabola in u, chosen by hand (`fix_symbolic(...,'x^2')`, "Best value at boundary" printed).
6. **Symbolic formulas are numerically fragile and not interpretable.** The direct-symbolisation F is a sum of four sinh/cosh terms with coefficients of order 1e-4 to 5e-3 and arguments near -9 (cell 25), nested bessel/sinc/arcsinh; rounding to 4-5 digits changes MAPE from 0.0042 to 0.146 (XJTU direct symbolisation, `PIKAN_XJTU_Var2` cell 29), and for the prior-guided variant from 0.0058 to 0.101 (XJTU), 0.0089 to 0.215 (HUST), 0.0083 to 0.072 (TJU); MIT is unaffected (0.0076). No sparsity regulariser is used during training, so the pykan symbolic step operates on a dense, unpenalised network.
7. **Metric argument order bug (all tables).** `utils/util.py:80` defines `eval_metrix(true_label, pred_label)` but every call site passes `(pred_label, true_label)` (e.g. `Model/PIKAN_opt.py:231`, `main_our_models_optimize_XJTU.py:80`), so sklearn's MAPE divides by the prediction instead of the truth. MAE and RMSE are unaffected. Small numerical effect for SOH in 0.7-1.0 but it is selection-relevant, because MAPE is the criterion that picks the best (alpha, beta). The same call order appears in PINN4SOH, so published baselines share it. The notebooks call `eval_metrix(true_label, pred_label)` correctly in the symbolic comparison cells but incorrectly in `Test` cells.
8. **Validation = neighbours of training pairs** (random pair split, `dataloader.py:158-159`), so validation MSE is almost a training metric and early stopping behaves as a training-loss stopper (consistent with the model fitting without overfitting alarms). PINN4SOH's paper says it divides "training, validation and test batteries" 6:2:2 (Wang et al. text near Table 2) while the released code splits validation by pair, not by cell: paper and code disagree there.
9. **Unequal tuning in the headline comparisons** (section 4): PIKAN and PINN get a 49-point search on test; MLP, CNN, KAN, Transformer get none, and a shorter patience of 10.
10. **Tiny test sets**: 2-3 XJTU test cells per batch, test cells fixed by file name; the 10 seeds vary only initialisation and the pair shuffle, so the stated stability is not cell-sampling variance. No confidence intervals or paired tests anywhere.
11. **Seed-dependent, OS-dependent selection of small-sample training cells** (`os.listdir` order, then `[:n]`).
12. **Unsafe artefacts:** `.pt` / `.pth` files are pickles loaded with `torch.load` (default, no `weights_only`), do not load them; the environment file pins old versions (`pikan.yaml`, python 3.10, pinned pip list, Chinese mirror).
13. **Code state not matching README claims**: `main()` in `main_our_models_optimize_XJTU.py:108` runs only batch index 5 ('satellite', `range(5,6)`), `main_2()` only batch 0; the README tables for batches 1-6 imply editing the loops (the repo state is a mid-experiment snapshot). Default `model_name` argparse `choices` omit `PIKAN_opt` (`:220`), but the code sets the attribute afterwards.

## 7. What the method cannot do
- **No forecasting.** It maps features of the charge segment of cycle k (and t_k) to SOH_k. It cannot predict a future trajectory, EOL, or RUL; and since t is life fraction it cannot even be applied to a cell whose total life is unknown. (Their abstract says "estimation", the notebooks call the estimates "forecast".)
- **No extrapolation beyond observed cycles** (inputs normalised by whole-life range; nothing generates unseen cycles; the G network is never integrated forward).
- **No interpretable degradation law in a usable sense**: the symbolic G is a dataset-specific parabola, F's symbolic form is a fragile sum of hyperbolic functions (section 6, items 5-6).
- No temperature, C-rate, DOD or protocol inputs (all that is encoded is 16 summary statistics), no uncertainty output, no handling of cells with missing charge-segment data.
- Needs full charge to V_end and CV down to 0.1 A (feature definition), so partial charging cannot be handled.
