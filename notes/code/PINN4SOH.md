## 1. The model as equations
Paper notation: u = SOH, t = cycle, x = health indicators. Paper Eq. (1) u = f(t, x); Eq. (2) du/dt = g(t, x, u; ...) "explicit PDE"; Eq. (3)-(4): g is replaced by a network G, and H := dF/dt - G(t, x, u, u_t, u_x; theta) is the residual, with F(t, x) the solution network (text of Methods, "Physics-informed neural network"). Eq. (5) SOH_k = Q_k / Q_0. Eq. (6) L_PDE = sum_i H(t_i, x_i)^2. Eq. (7) L_data = sum (u_i - u_hat_i)^2. Eq. (8) L_mono = sum_j sum_k ReLU(u_hat_{k+1} - u_hat_k) (text extraction of the PDF is partly garbled; read as the sum over batteries j and cycles k). Eq. (9) L = L_data + alpha L_PDE + beta L_mono.

Implementation (`Model/Model.py`):
- **Solution network** (`:64-77`): encoder = MLP 17 -> 60 -> 60 -> 32 with **sin** activations and dropout 0.2 between hidden layers, then a predictor Dropout(0.2) - Linear(32,32) - sin - Linear(32,1) (`:51-62`). Input = 16 features + cycle index (all scaled to [-1,1], see section 3). Output u = SOH. Xavier-normal initialisation (`:79-86`).
- **Dynamics network** (`:138-141`): `MLP(input_dim=35, output_dim=1, layers_num=3, hidden_dim=60, dropout 0.2)`, with sin activations. Input is `cat([xt, u, u_x, u_t])` = 17 + 1 + 16 + 1 = 35 (`:232`).
- **Derivatives** (`:216-235`): `u_t = grad(u.sum(), t)`, `u_x = grad(u.sum(), x)`, `create_graph=True`; residual `f = u_t - G(...)` (`:234`).
- **Losses per pair of consecutive stored cycles (k, k+1)** (`:247-258`):
  - L_data = 0.5 MSE(u_k, y_k) + 0.5 MSE(u_{k+1}, y_{k+1})
  - L_PDE = 0.5 MSE(f_k, 0) + 0.5 MSE(f_{k+1}, 0)
  - L_phys = sum over the batch of ReLU[(u_{k+1} - u_k)(y_k - y_{k+1})]  (`:255`, a **sum**, label-dependent; differs from the paper's Eq. (8), see weaknesses)
  - L = L_data + alpha L_PDE + beta L_phys  (`:258`)
- Weights (alpha, beta) per script default: XJTU 0.7 / 0.2 (`main_XJTU.py:99-100`), HUST 0.6 / 0.1, MIT 0.5 / 0.01 (`main_MIT.py:30-31`), TJU 0.1 / 0.1 (`main_TJU.py:38-39`); small-sample XJTU uses alpha 0.5, beta 10 (`main_XJTU.py:56-57`). `main_MIT.py:85-97` keeps a `grid_search()` function (grid reduced to one point), so a grid search existed; selection criterion not visible. `fix.md` (Chinese, dated 2026-09) says the initial code version had bugs which were fixed, "so that the alpha and beta values are not consistent with those in the Supplementary File; other code unchanged". The bug is not identified.
- Monotonicity or other constraints: only L_phys above; no architectural monotonicity.
- Optimiser etc. are the same as PIKAN (see below); PIKAN's code is a direct fork.

## 2. KAN
None. (Sine-activation MLPs with dropout 0.2.) PIKAN replaced both F and G by efficient-kan networks and removed u_t from G's input (see `PIKAN.md`).

## 3. Data
- **Datasets** (paper "Data generation", Table 1): XJTU (new, 55 NCM cells, 6 charge/discharge protocols, batches 1-6; 8 cells per batch except batch 2 with 15; LISHEN 2000 mAh, 4.2-2.5 V, room temperature), TJU (Zhu et al.: NCA, NCM, NCM+NCA; 25/35/45 C; 0.25-4 C), HUST (Ye et al.: 77 LFP cells, one charge protocol), MIT (Severson et al.: LFP fast charging, 30 C). Paper counts 310,705 samples of 387 cells (the repo file counts, checked in the PIKAN copy of the same CSVs, are XJTU 55, TJU 130, MIT 125, HUST 77 = 387, consistent with the paper).
- **Features** (paper "Feature extraction", `data/*/*.csv`): from the last 0.2 V of the constant-current charge voltage curve (V_end - 0.2 V to V_end) and the CV-stage current between 0.5 A and 0.1 A: mean, std, kurtosis, skewness, charge time, accumulated charge (CC Q / CV Q), curve slope, curve entropy for voltage and for current = 16 features. Plus cycle index. Columns in the files: voltage mean, voltage std, voltage kurtosis, voltage skewness, CC Q, CC charge time, voltage slope, voltage entropy, current mean, current std, current kurtosis, current skewness, CV Q, CV charge time, current slope, current entropy, capacity (checked in `refs/code/PIKAN/Data`, which redistributes the same CSVs).
- **Label:** SOH = capacity / nominal capacity (nominal 2.0, 1.1, 1.1, [3.5, 3.5, 2.5] Ah; `dataloader.py` same as PIKAN's).
- **Normalisation:** identical dataloader to PIKAN (the PIKAN version differs only by `.to(device)`, diffed): `read_one_csv` inserts `cycle index = arange(n)`, drops any row with a 3-sigma outlier in any column **including capacity**, then min-max scales all input columns **per cell** with that cell's whole-life min and max (`dataloader/dataloader.py:44-67`). So t is life fraction and the scaling of a test cell uses its end-of-life. The paper states only "min-max normalization is performed on the features ... in [-1,1]" (text under "SOH estimation"); the per-cell, whole-life nature of it is not stated there.
- **Split (cell-level):** XJTU: within a batch, files whose name contains '4' or '8' are test (`main_XJTU.py:14-18`), others train; HUST: 20 listed ids (`main_HUST.py:42-`); MIT: id % 5 == 0 (`main_MIT.py:42-46`); TJU: index units digit 5/9 or 4/8 (`main_TJU.py:57`). The paper says train / validation / test batteries are split about 6:2:2 and test batteries are "evenly distributed" (Tables S2-S6, not read); **in code the validation set is a random 20 % of consecutive-cycle pairs of the training cells** (`dataloader.py:158-159`, `train_test_split(..., test_size=0.2, random_state=420)`), not separate batteries. Test cells never enter training; validation does not have independent cells.
- Leakage-type issues: per-cell whole-life scaling and 3-sigma filtering with test labels; test metrics are computed whenever validation improves (logging only, `Model/Model.py:293-298`). Hyper-parameters alpha, beta, lr per dataset were chosen by an unreported rule (a `grid_search` function exists). Treat the published numbers as in-protocol and slightly optimistic; do not use this repo's protocol as ours.

## 4. Training
Adam for F: warm-up 30 epochs 2e-3 -> 1e-2 then cosine to 2e-4 (200 epochs max) (`Model/Model.py:94-120`, `main_XJTU.py:86-91`); Adam for G with constant lr_F (1e-3 XJTU, 5e-4 HUST, 1e-3 MIT/TJU); batch 256 (XJTU) / 512 (others) / 128 (small-sample); early stopping patience 20 on validation MSE of F (`Model.py:308`); best state kept at lowest validation MSE. **No random seed is set anywhere** (`utils/util.py` has no seeding function; each run is "repeated 10 times", paper text "Fig. 4b"), so reported means are not exactly reproducible (the README says so itself). Baselines MLP, CNN: same optimiser/schedule, one configuration, patience 10 (`main_comparision.py:106`).
Fine-tuning (`main_adaptation - fine-tuning.py`): load source model, freeze G, fine-tune F only on one target-domain cell (`small_sample=1`, `:220`) with a hand-set learning rate per target (`:242,254,268,276,297`), early-stop patience 10.

## 6. Hidden assumptions, bugs and weaknesses
1. **Degenerate PDE loss.** G receives u_t as an input (`Model.py:138,232`; paper Eq. 4 lists u_t among G's arguments) and the residual is u_t - G(...). G can satisfy L_PDE = 0 by copying that input, independent of any degradation physics. The paper's claim that G "learns the degradation dynamics" and "is independent of protocols and datasets" (frozen in transfer, Methods) is therefore not guaranteed by the loss. PIKAN removed u_t from G's input.
2. **Paper vs code: monotonicity loss.** Paper Eq. (8) penalises any predicted increase; code `Model.py:255` penalises sign disagreement with the true label step, in both directions, and is a sum over the batch. The paper does mention capacity regeneration, but the code term needs labels.
3. **Paper vs code: validation.** Paper: validation batteries (6:2:2 by battery). Code: random pair split inside the training cells.
4. **Not seeded**; alpha, beta, lr hand-set per dataset; post-publication bug fix (`fix.md`) with changed alpha/beta, so published supplementary hyper-parameters do not reproduce the released code.
5. **Per-cell whole-life min-max incl. cycle index** (same dataloader as PIKAN): t equals life fraction; needs end-of-life of the test cell. Shared with PIKAN (see `PIKAN.md` section 6.4).
6. **Features are summaries of a 0.2 V charge window and CV tail:** needs a full charge to V_end and CV down to 0.1 A. CC Q and CC charge time are collinear at constant current (the PIKAN notebook comment says "CC Q is equivalent to CC charge time at constant-current charging"), so the 16-feature input has duplicated information; high feature-SOH correlation within a dataset (paper Fig. 3b) is a within-dataset property, not a cross-chemistry one: the paper itself reports that correlation signs flip between NCM/NCA and LFP datasets (feature 9-10 and 11-16).
7. **Test-set evaluation at each validation improvement** (logging only) and small test sets (XJTU 2-3 cells per batch).
8. **Gains are concentrated in small-data settings:** the authors state that with many training samples (HUST, MIT) a same-size MLP or CNN performs comparably; the headline superiority is for XJTU and the 1-4 cell small-sample runs, whose test sets are 2-3 cells per batch.
9. **Metric argument order:** `eval_metrix(true_label, pred_label)` (`utils/util.py:42`) called as `eval_metrix(pred_label, true_label)` (`Model.py:296`), so MAPE divides by the prediction (MAE, RMSE unaffected). PIKAN inherits it.
10. Pickled `.pth` files; no LICENSE file in the repository (checked: none in `git ls-files`).

## 7. What the method cannot do
Same as PIKAN: no forecasting of future SOH or RUL, no use without the features of the target cycle, no extrapolation beyond observed cycles, no explicit degradation law (G is a black-box network; "stable modelling and prognosis" in the title refers to estimation stability; the paper's "prognosis" is not demonstrated as forecasting in the sections I read). No temperature, current-rate or protocol covariates beyond the 16 summaries. No uncertainty.
