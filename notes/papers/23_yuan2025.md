## Problem and stated contribution
Multi-step SOH forecasting from charge-curve health features (HFs), using (i) an xPatch backbone (EMA trend/periodic decomposition, patching, depth-wise CNN for the periodic stream, MLP for the trend stream), (ii) a self-supervised pre-training with three equal-weight losses (masked reconstruction, denoising, prediction), and (iii) parameter-transfer fine-tuning with the CNN frozen and the MLP and the final linear layer updated (Fig 7e, p.9). Claims: average SOH R2 0.964 and "R2 improved by 2.1 % compared to direct training" (abstract p.1; Section 4.3 p.14), MAE down 24.6 %, RMSE down 26.0 %.

## Data
- Three public sets: HUST (LFP, 1.1 Ah, 30 C, 0.2 Hz), MIT/Stanford-Toyota (LFP, 1.1 Ah, 30 C, 1 Hz), XJTU (NCM 2.0 Ah, room temperature, 1 Hz) (Table 1 p.3, verified on the image; the text extraction scrambles the columns).
- Inputs: the same 16 charge-stage HFs as Wang et al. 2024 (ref 33): mean, std, kurtosis, skewness, slope, entropy of V and I, accumulated charge and duration of the CC and CV phases (Section 2, Eq. 2-9, p.5). They are z-scored (Eq. 10, scope - per cell or per dataset - not stated).
- Label: SOH = C_m / C_n x 100 (Eq. 1, p.2). In Fig 1c (p.3) the HUST SOH starts at about 105 %, MIT scatter reaches about 98 %, XJTU rises to about 98 % before declining, so SOH is not normalised by a common first-cycle capacity across sets. The text says MIT SOH noise comes from equipment failures during discharge (p.5).
- Cells and splits (Table 2 p.9): pre-training = HUST batches 9 and 10, MIT batch 3, XJTU batches 2 and 3. Model comparison = train on first 50 % of cycles of cells 3-8 of HUST batch 7, validate on last 50 % of the same cells, test on cells 1 and 2 of that batch (and the analogous MIT batch 2 cells 31-36 / 37-38, XJTU batch 4 cells 3-8 / 1-2). Transfer = target batches HUST 1, MIT 1, XJTU 6: fine-tune on first 50 % of cells 5-8 (MIT 6,7,9,10), validate on last 50 % of the same cells, test on cells 1-4 (MIT 1,2,3,5).
- So test cells are cell-disjoint (2 cells per set in model comparison, 4 per set in transfer), but the validation set shares cells with the training set (temporal split inside a cell) and test cells come from the same batch (same protocol) as the fine-tuning cells.
- Window: sequence length 30 (Table 3 p.10); output length O in {1, 4, 8, 16} cycles (Introduction p.2; Table 5).
- Section 4.3 text says the XJTU test cells are "first batch Nos. 1-4" named X6-1..X6-4; Table 2 says sixth batch. Fig 16 caption says X1-2 while Table 10 says X6-2.

## Model
- xPatch (ref 45): channel-independent over the D=16 features; EMA decomposition with smoothing factor alpha = 0.3 (Eq. 11-14); patch length P = 16, stride 16 (Eq. 15-16, Table 3); depth-wise + point-wise CNN branch (Eq. 17-21) for the periodic part; MLP branch with average pooling and layer norm for the trend (Eq. 22-24); concatenation and a linear head to O outputs (Eq. 25-26). Parameter count 8,816 (O=1) to 13,067 (O=16), average 10,594 (Table 6 p.12).
- Pre-training: random masking (fraction not stated), Gaussian noise variance 0.1, prediction of the next window; total loss (L_r + L_n + L_p)/3 with equal weights (Eq. 27-30, p.8). Huber loss, 200 epochs, batch 8, lr 1e-3 (Table 3). Transfer: 50 epochs, MSE, lr 5e-4, CNN frozen.
- Physics prior: none. There is a statement that the EMA split into "trend" and "fluctuation" is not meant to decouple aging mechanisms (p.7); the trend stream is labelled "irreversible aging" in prose only.
- KAN: none.

## Tuning
No tuning procedure is reported. Hyperparameters of xPatch (Table 3) and of baselines (Table 4 p.10; Transformer with 4 encoder layers, 1 decoder layer, d_model 16, 8 heads; PatchTST patch 16; DLinear; the column alignment of Table 4 is scrambled in the text extraction) appear as single configurations. How they were chosen, and on which cells, is not stated. Whether the test cells influenced them cannot be excluded. The comparison metric CES (Eq. 34, p.10) is a sum of min-max normalised parameter count, MAE, RMSE, R2 over four models; sign convention of "norm" for parameters/errors vs R2 is not defined and the numbers (Transformer 0, DLinear 3.214, PatchTST 1.885, xPatch 3.471, Table 6) depend on which four models are in the set.

## Evaluation
- Metrics: MAE, RMSE (percent SOH), R2 (Eq. 31-33). Averaged over the O-step horizon and over the test cells.
- Model comparison (Table 5, p.12), average over 6 test cells x 4 horizons: xPatch MAE 0.785 %, RMSE 0.961 %, R2 0.954; DLinear 0.926 / 1.228 / 0.919; PatchTST 1.106 / 1.413 / 0.899; Transformer 1.401 / 2.016 / 0.839.
- Strategy comparison (Tables 7-9, pp.15-16; PT = pre-trained only, DT = direct training on target, TL = pre-train + fine-tune): averages over cells and horizons, HUST PT 1.748 / 1.790 / 0.945 vs DT 1.321 / 1.329 / 0.969 vs TL 0.974 / 0.977 / 0.983 (MAE %, RMSE %, R2); MIT PT 0.614 / 0.759 / 0.761, DT 0.311 / 0.380 / 0.926, TL 0.247 / 0.313 / 0.943; XJTU PT 1.714 / 2.224 / 0.716, DT 0.770 / 1.030 / 0.937, TL 0.588 / 0.736 / 0.967. I re-derived the headline: mean of TL MAE over the three sets = 0.603, of DT = 0.800 (-24.6 %); RMSE 0.675 vs 0.913 (-26.0 %); R2 0.9643 vs 0.944 (+2.1 %). The headline arithmetic is correct and the 2.1 % is a relative R2 gain from 0.944 to 0.964.
- Noise test (Table 10, p.18): adding noise at SNR 25/50/75/100 to the test data of three cells (H1-2, M1-2, X6-2); average R2 0.648 / 0.958 / 0.967 / 0.974. At SNR 25 the MIT cell R2 falls to 0.06-0.20.
- Seeds / repeats / confidence intervals / statistical tests: none stated. Single run per configuration. No spread in any table.
- Baseline note: in Table 5 xPatch is not best in every cell: e.g. X4-2 O=4 MAE 0.906 vs Transformer 0.811, DLinear 0.597, PatchTST 0.778; M2-37 O=16 RMSE 0.847 vs Transformer 0.748. The text claims best performance "across the three evaluation metrics" (on average).
- Evaluation covers the whole life of each test cell (Fig 8 curves from near 100 % down to about 80 %); the text does not state whether the O-step output at cycle k uses HFs of cycles after k (estimation) or only up to k (forecast). Section 3.2 says the model predicts the future HF sequence and the abstract speaks of forecasting; Fig 4 stage 3 feeds the target-domain HFs together with a calculated SOH curve. I could not settle this from the text.

## Ablations
- Model backbone comparison (Table 5), strategy comparison PT / DT / TL (Tables 7-9), noise robustness (Table 10), horizon dependence (Fig 15).
- Not done: effect of each SSL loss term (reconstruction, denoising, prediction), mask ratio, noise variance; freezing the MLP instead of the CNN; supervised pre-training on the same source cells; fraction of target data used for fine-tuning; xPatch without SSL but trained on the pooled source+target cells.

## Hidden assumptions
1. The target batch (same protocol) provides 4 fully labelled cells (first 50 % of cycles) for fine-tuning; the TL gain is measured in that setting.
2. The same 16 HFs are available and comparable across sets; MMD below 0.1 is taken as sufficient similarity (p.8).
3. Test cells are representative with n = 2 per set (model comparison) and n = 4 (transfer).
4. Nominal capacities and SOH normalisation differences across sets (HUST above 100 %) do not harm transfer.
5. DT, PT and TL share the same data split, so the TL gain is attributed to the SSL objective; but TL also sees more cells (the pre-training batches), which is a confound.

## Weaknesses a reviewer would hit
- The TL-versus-DT gain mixes two things: the SSL objective and simply more training cells. No control with supervised pre-training on the same source cells, no SSL-term ablation.
- Single run, no seeds, no spread, no test: a 0.2-0.4 point R2 difference is not interpretable. Violin plots spread over cell x horizon, not over seeds.
- Very small test sets (2 or 4 cells per set); validation shares cells with training (temporal 50/50 split inside the cell).
- Test and fine-tune cells come from the same batch (same protocol): the "different battery types" generalisation is a same-batch transfer; no leave-batch-out or cross-chemistry target without labelled cells.
- Whether future HFs leak into the O-step output is not clear (see Evaluation).
- Inconsistencies: XJTU test batch named first in text and sixth in Table 2; X1-2 vs X6-2 (Fig 16 vs Table 10); Fig numbering in the running text (Fig 8 called a radar chart; Fig 9 cited for loss curves; Fig 13 and Fig 14 swapped) does not match the figures.
- CES (Eq. 34) is an ad hoc sum of min-max-normalised quantities over four models; its value 3.471 vs 3.214 has no scale.
- SOH defined against nominal capacity gives HUST SOH above 100 % (Fig 1c); the metric (percent) mixes datasets with different SOH offsets.
- No physics: the title/abstract language of "degradation patterns" is not tested; no interpretation of what the model learned.
- Data "available on request"; no code statement (p.19): not reproducible.

## Gaps and hooks for our paper
- Same 16 HFs as PINN4SOH on the same three datasets (plus TJU): the HF space is a common benchmark; any KAN-physics model on it must beat xPatch-TL in horizon error (O = 1, 4, 8, 16 cycles) under cell-level folds, not only PINN4SOH.
- A claim that physics gives better multi-step extrapolation than xPatch can be tested with horizon-error curves like Fig 15 (a compact heat-map form); our experiments should run with seeds and cell-fold spread, which this paper lacks.
- Their own limitation (future work, p.18): cumulative error in multi-step prediction and RUL coupling. A law-based forecast (integrating a learned rate) has no autoregressive accumulation of the same kind; test integration error vs horizon.
- MMD analysis (Fig 7) could be matched by a stress-space coverage analysis in our paper: identifiability requires the stress range to be covered; they only check feature MMD.
- Do not copy: CES metric; Fig 7a-d bars; Fig 8 24-panel grid.
