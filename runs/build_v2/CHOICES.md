# build_v2 choices (conservative readings where the spec is ambiguous)

Format: item, the ambiguity, the reading taken, why it is the conservative one. Append-only.

## Item 1: nested subsets
1. **Standardisation (GAP-11).** Mean and population SD (ddof 0) over the fold's 32 training conditions; a coordinate with SD 0 keeps scale 1. Spec says "standardised by their mean and SD" without the ddof.
2. **Distance ties and the first pick.** Ties in the distance and in the nearest-to-centroid rule go to the smallest condition id (ids are sorted before selection, so the result does not depend on the order in which ids are passed). The "centroid" is the origin of the standardised space (= the mean of the 32 conditions).
3. **Constraint test.** Restriction to deficient temperatures is applied when `picks left within the first eight <= total deficit` (spec: "equals"; "<=" cannot differ because the deficit can never exceed the picks left, but it is the safer form). Required count per temperature is min(2, number available at that temperature).
4. **Random-subset variant (g1 downgrade row).** A seeded permutation of the 32 ids (SeedSequence([20261105, crc32("B|g1|randsubset|<fold>|<j>")])), first m taken, **without** the temperature constraint (literal reading: "3 seeded random nested subsets in place of max-min"). Unconstrained subsets can only make the row harder on A1 and D*, which for a downgrade row is the conservative direction.
5. **Where the thinning acts.** After the split-integrity check, on the cycling training cells only; storage cells and the test side are never touched. The 32 ids come from the split file (`train_cycling_conditions`), not from the cells on disk, so a partial download cannot change the subsets. m >= number of training conditions returns the same list object (m = 32 = Test B bit for bit, tested).
6. **ISU fallback.** The same selector on (charge_c, discharge_c, dod_pct) from `isu_conditions.csv` with no temperature constraint (ISU has no temperature factor). Not exercised by a test on real files (no ISU subset is part of the Samsung run list).
7. **Inner folds.** `inner_k` defaults to 2 for m in {8, 16} and 3 for m = 32 when `m` is set and `inner_k` is not given explicitly; `auto_budget` keeps this rule and lowers m = 32 to 2 only under the Partial plan.
8. **`subsets.json` pin.** `runs/prereg/subsets.json` was generated from the split identifiers only (`code/prereg/make_subsets.py`) and records the composition by temperature. The lab composition (Table 2 appendix) needs the laboratory of each condition, which comes from the data tables, and is not written here.

## Item 2: k = 0 / k = 2 paths
1. **Throughput at k = 0.** The window has no rate (one point), so the analytic DESIGN rate of the cell's stress vector (`spec.efc_rate`, label-free, same formula as the pipeline's analytic EFC) is the throughput after the reference; storage cells keep nu = 0. Spec says only "per-cell latents and offsets stay at prior means"; it is silent on the rate. The alternative (zero rate) would make every cycling cell look like storage.
2. **k = 2 and storage.** Storage cells use min(k, k_sto) window points (spec 5); a learner that needs window features drops storage cells with < 2 window points (existing m6 rule, unchanged). At k = 0 no window feature exists, so A11/A12 keep every cell and use stress + horizon only; the GP `min` feature set (which indexes window columns) is forced to `full` on empty window features.
3. **R1 and R2 are not scored at k = 0** (they need a window check-up; the spec says "R1, R2 need k >= 1").
4. **A9 and A2 at k = 0.** Their window inversion starts from z = 0 and delta = 0 and the data term of a reference-only window has zero gradient; the code additionally forces z = delta = 0 for any cell whose window has one point, so the result does not depend on optimiser round-off.
5. **Tuning window.** With `m` set, inner CV is scored at k = 2 (m < 32) or k_full (m = 32), tuned once per (fold, m), and the tuned configuration is applied at every k (spec 4.1). With `m` unset the legacy window is unchanged. A11/A12 and D* learners retrain per k; every other arm is fitted once and predicts at each k.
6. **File layout of a grid run.** `k: "grid"` scores (0, 2, "full") from k_full = `window.k_cycling` (k_full = 2 gives (0, "full"); k_full < 2 raises `DesignReopenError`). The k_full cell keeps the file names the statistics step reads (`condition_scores.json`, `cell_scores.json`, `condition_meta.json`); the other cells are `*_k0.json`, `*_k2.json`; predictions carry phase `outer_test_k<k>`. `condition_scores.json` is written last (marks a scored run).
7. **NC-1 on the grid.** Predict-stage invariance runs for every arm, seed and k, each time scrambling labels after THAT k's window (so k = 0 is checked against every post-reference label). `nc1_full` scrambles after the largest window (k_full) and compares all k cells; the per-k stage check carries the k = 0 and k = 2 guarantees.
8. **Margins at grid cells.** `margins.json` still holds the inner-CV E at the tuning k only (descriptive pp-scale row); per-cell E at k = 0 and the other k is not built (the log-scale test does not use it). Listed in RESULT.md.

## Item 3: A15 / G15 symbolic extraction
1. **One code path.** `arms.SymbolicArm` serves both arms; they differ only in the parent stress map (A15: KAN [d,h,1] with h in {1,2}; G15: the additive GAM of A4 = KAN [d,1]) and in the tuned space (A15 = A1's six dimensions with h restricted; G15 = A4's four). The calendar KAN [1,2] is extracted identically in both (two edges from SOC; Arrhenius is not eligible on SOC edges).
2. **Tuning.** A15 and G15 are tuned as the arm that is scored (every trial = parent fit + extraction + refit, about 1.5 x an A1 fit), with the same N trials and inner folds as every other tuned arm. The alternative (tune the parent KAN, extract once at the end) would make the tuned objective differ from the scored object.
3. **Refit.** End to end under the unchanged PINN loss (data + residual + priors + coefficient ridge), warm start from the parent's solution network, latents, offsets and law levels, `refit_frac` = 0.5 of the parent's steps (config `symbolic.refit_frac`), same optimiser recipe (clip 20, warm-up 0.4, lr 5e-3). The KAN sparsity term has no symbolic analogue (pruning is done by the BIC rule) and is 0; the spline-L2 term becomes a ridge on all symbolic coefficients with the tuned `l2`.
4. **Positive abscissa for power and log.** Physical stress value (temperature in kelvin, SOC, DoD, C-rates), floored at 1e-6; for hidden-layer edges (no physical abscissa) the edge's own hull rescaled to (0.05, 1.05]. Constant additive terms are part of every non-zero family (no separate "constant" family in the frozen library).
5. **BIC noise floor.** tol = 1 % of the largest edge range of the layer (rule 3 of the frozen rule): without a floor, spline approximation error would be read as structure and BIC would always choose the richest family; with a per-edge floor no edge could ever be pruned. The 1 % constant and G = 101 grid points are part of the hashed rule.
6. **Cap.** `symbolic.cap` in the run config or `max_coeffs_per_edge` in `symbolic_library.json` (null). Extraction raises `CapNotSetError` while both are unset, so no A15/G15 run can start before the method-architect fills it. `library_hash` covers the library and rule but not the cap (the cap is a separate pin, PREREG_v4 18 2b). The file stores the hash and a test checks it equals the code.
7. **Training-side BIC of a law** (printed beside K2) = n ln(train data MSE) + (coefficients + 2 level parameters) ln n, with n the number of training observations and the data MSE of the refitted model in y_s units.
8. **Not built here:** the stability metric over a Latin hypercube and the per-input family-label table across folds (11a item 6) and the figure inputs for Fig. 5; the per-edge reports needed for them are in `arm.report` (families, coefficients, BIC tables, input family labels).

## Item 4: D* options, h = 1
1. **h = 1 in three arms.** `H_GRID = [1,2,3,4,6,8]` is the map space of A1, A2 and A13 (7.1 defines A2 as "A1 without lam_res and F" and A13 as "as A1"); A15 uses {1, 2}. A2 gaining h = 1 is a reading of that table row, not an explicit D016 line.
2. **"Transformed inputs".** The A3 abscissae are `law.ParamMap.feats` (Arrhenius abscissa of T, SOC_mid and SOC_mid^2, log DoD, log C_ch, log C_dch; storage rows keep their (T, SOC) and the log columns sit at the A3 clamp). "t and EFC raw and log" = t_n, E_n (the PINN's scaled time and cumulative throughput at the forecast point, from the causal curve), log(t_n + 1e-3), log(E_n + 1e-3). The raw and transformed sets replace each other (the transformed set does not also carry the raw stresses).
3. **Wrapper, not edit.** P3's `feat_rows` is wrapped at import (pilot code stays unedited); a cell without an `extra` block goes through P3's own code, bit for bit (tested). The extras sit before the horizon column, which stays last (the LightGBM monotone constraint and the GP 'min' set are unchanged; 'min' keeps the extras).
4. **Storage rows "out".** The learner trains on cycling cells only; `n_train_used` reports it. "in" keeps every cell that has enough window points (the existing m6 rule).
5. **A12R.** The descriptive "raw-feature-only LightGBM" is arm id `A12R` (A12's space without `feat`, `feat` fixed to raw, storage rows tuned). It is not a D* candidate.
6. **D* and AG selectors** (`selectors.py`) take only a dict of inner-CV scores; ties go to the candidate order; run writes `comparators.json` after tuning (inner or confirmatory). The statistics step must read the choice from there (item 5). At m < 32, AG = A4 and A5 is refused by the run (`ConfigError`).
7. **Optional GRU member of D\***: not built (J16 drop order 3). Needs a change-log row striking it, or the lead's call.

## Item 5: statistics step (D018 folded in)
1. **Where.** `code/pinnkan/stats_v4.py` holds the Design R2 statistics; `stats_step.run_stats_v4` is the entry point (it checks the item (f) guard first). The V3 builder in `stats_step.py` stays for history and is marked out of scope in item 7. `stats_step.nc2` now takes the ruled rule by default (30 of 40); the plain 27 of 40 is `sign_rule=stats_v4.PLAIN`.
2. **Sign rule config.** `sign_rule` ("betabin" or "plain"), `rho_s0`, `graph_w`, `alpha`, `e1_prime_approved`, `k_chain_struck`. The original instruction was to leave the rule unset until D018 ruled; D018 is ruled (Beta-binomial, rho_s0 = 0.03), so the default holds that value. Setting `sign_rule` to None, an unknown kind, or `betabin` without a valid `rho_s0` raises `SignRuleNotSetError` (the run refuses to score). Ties with a margin are dropped and n reduced (PREREG_v4 9.3); critical counts are always computed from n and the level, never stored.
3. **Graph.** Default w = 1/2 on P1N, 1/2 on K1; `graph_w` overrides it (0.78 gives levels 0.0195 / 0.0055 and counts 30 / 32; tested). Absent K arms (or `k_chain_struck`) put weight 1 on P1N and give the K nodes p = 1, so P is tested at 0.025. The graph is run on the Beta-binomial p-values; the p <= alpha w comparison is the same as the count threshold.
4. **Secondary family.** One p-value per node: for Q-A10 the larger of the two forms' p-values (the test holds iff both forms hold, i.e. the lowest tier over the forms); reverse S = reverse S in either form, tested at the slot level = max over the slot's two nodes of (level at rejection if rejected, else the final level). Second A10 form = arm id `A10P` (as published, factor 1).
5. **Estimated rows.** Simultaneous level 1 - 0.05/(number of cells present) with the fallback ranks (rank 8, [L(8), L(33)] at n = 40, 9 cells); the unadjusted 95 % intervals in the sentences use rank 11. Relative-reduction conventions as PREREG_v4 section 1. Mean pp BCa uses `SeedSequence([20261105, crc32(label)])` with labels `B|<contrast>|g<m>-<k>|BCa_mean_pp`.
6. **Sentences.** Constants are tested to be substrings of the D016 judge text (and the titles of PREREG_v4 section 11). Two joiners are not fixed by the table and are my reading: P-/K= and P-/K- use "whereas" (as P-/K+) for the K= clause and the table's own "while" for K-; the K- clause after a P+ or P0 part is joined with ", ". `(interval)` is filled as "95 % interval [a, b]" (the unadjusted fallback interval of the relative reduction). For T9 the [W] is the smallest reverse effect among the A10 forms that are reverse S (the weaker, conservative statement).
7. **Extent clause and "most".** e1 requires P2 and P3 in the graph; the GAP-1 d_c test (30 of 40 under the rule, outside the graph) decides "most". If e1 is reached, "most" fails and `e1_prime_approved` is False, e1 is used as approved (D018: "if he declines, e1 is used as approved and d_c is reported descriptively"); with approval the clause e1' is used. e1' is Shlok's decision (freeze condition A6) and stays off by default.
8. **Item (f).** `write_item_f` writes the report plus a hash record with the write time; `require_item_f` raises `ItemFError` if the file or hash record is missing, the hash differs, or the file (or its recorded time) is not strictly earlier than every `condition_scores*.json` of the runs. `item_f_from_runs` computes the estimate from the inner-CV training-side scores (`tuning_done.json`), grouping by (outer fold : inner fold) and by majority laboratory (`train_condition_meta.json`, new run output, identifiers only). Reported evidence; no count depends on it.
9. **Not built in this item:** Test C / S2 descriptive tables and the Test C abstract rule (item 6), the downgrade rows (item 6), margins.json per contrast and cell, figure inputs for Fig. 4 and Fig. 5.
