## 1. Claim contract

- **Question (J16 1.1).** How few cycling ageing tests and early check-ups does a physics-informed neural network (PINN) with Kolmogorov-Arnold (KAN) stress functions need to forecast held-out cycling conditions of the Samsung INR21700-50E campaign? How much of any advantage comes from the physics law and how much from the KAN? Does the KAN yield a closed-form stress law that predicts held-out conditions at least as well as an equally simplified additive law? The word "few" applies to **cycling** conditions only: the 132 storage cells stay in training in every grid cell, so titles say "few cycling tests", never "few ageing tests".
- **Claims, each with its own gated test (sections 2 and 9).** *PINN role, chain P:* **P1** at the scarce cell g1 = (8 cycling conditions, 2 check-ups) the PINN-KAN (A1) has a lower median held-out-condition error than the best tuned data-driven learner D\*; **P2** the same network without the physics law (A9) is worse at g1; **P3** the advantage over D\* is larger at g1 than at the cell (32, 2), which has four times as many cycling conditions and the same two check-ups (D034, AD1: the same window, forecast set and caps at both cells, so that only the number of cycling conditions differs; the full-data cell g4 stays the cell of K1 and K2 and an estimated cell). *KAN role, chain K:* **K1** at g4 the closed-form law extracted from the KAN (A15) is non-inferior to A1; **K2** at g4 A15 is more accurate than an equally simplified additive law (G15). *Qualifiers (secondary family):* Q-H (A1 against the hard ODE A2), Q-A10 (A1 against the dataset authors' model) and Q-T (training with and without storage cells). Nothing else is a claim.
- **Estimand (D012; J16 section 2).** Unit = held-out condition (Test B, n = 40). For a contrast with target arm T and comparator arm C at grid cell g, L_c = ln(S_C,c / S_T,c) with S the condition score (section 6); L_c > 0 favours T. The confirmatory test is the **sign test with a fixed design effect** on L_c - m (9.3; assumption-based, rho_s0 = 0.03; the plain exact sign test is a descriptive independent-conditions row); the estimand is the **median condition**, with the three laboratories as fixed design strata (9.1). Conventions for the abstract numbers (fixed here because V3 and T1 carry a sign slip in "1 - exp(median L)"; the code uses the form below): a relative error reduction is X = 100 (1 - exp(-median L)) %; an excess "is Y % worse" is Y = 100 (exp(median L) - 1) % with L taken in the direction that makes it positive; both come with the exact order-statistic 95 % interval transformed the same way. The mean-based pp difference with a BCa interval and the worst-condition error are descriptive companions (section 9.8 rule 1). **Methods defines (D033 M6):** X is the transformed median of the per-condition log ratios (the relative error reduction of the median condition, not a difference of median errors), and "the best tuned data-driven learner" D\* is the inner-CV winner per (outer fold, m) among A9, A11 and A12 (7.4), not the learner that is best on the held-out conditions.
- **Mechanism.** (1) The soft residual holds a shared surface F to a **single state-dependent modulation** of the sum of a time-driven and a throughput-driven rate where there are no data (beyond the window, between conditions, at 35 C storage twins). (2) A hidden-layer KAN stress map represents interactions of (T, SOC window, DoD, C_ch, C_dch) without prespecifying them; hidden width h = 1 is in the grid, so at m = 8 the map can collapse towards a near-additive form. (3) The hypothesis behind P3 is that a physics prior pays when cycling conditions are scarce and matters less as they grow. The law is never called "independent superposition" (D013 (a)).

## 5. Task, window rule, forecast set

- **Task (identical for every arm).** Inputs: stress vector s (cycling: T, SOC_mid, DoD, C_ch, C_dch; storage: T, SOC), Q0,c, window check-ups, throughput rate nu. Output: retention at every later check-up time. Time t_tilde = days since the reference check-up (t_n = days / 500), global scaling only.
- **Throughput.** Inside the window: logged (analytic `efc_est_cum` of the pipeline) equivalent full cycles; after the window: the cell's own mean rate over the window (causal). **Validation rule (fixed now; FB-5 met, 17.1):** analytic EFC versus ZYK-logged EFC for at least 2 cycling cells per DoD class and per laboratory, at every check-up. Accept analytic throughput iff the median absolute relative
  difference is <= 5 % and no sampled cell exceeds 10 % at its last check-up; otherwise ZYK-logged throughput is used for every cycling cell (`throughput: zyk` is implemented in `pinnkan/zyk.py`). An oracle-throughput row is a sensitivity either way.
- **ZYK completeness and DoD classes (D24 1; FB-5 met, 17.1).** A ZYK file is **incomplete** iff a gap above 600 s has at least one endpoint with |I| > 0.05 A, or time is not monotonic, or the current has a NaN, or the file has fewer than 10 rows, or a rest-only gap exceeds 24 h (constants `ACTIVE_I_A` = 0.05, `GAP_FLAG_S` = 600, `REST_GAP_MAX_S` = 86400, `MIN_ROWS` = 10; `dt_max_s` kept as information). Reason: the coordinate is discharged charge over 4.9 Ah by the trapezoid rule, so a gap loses or invents throughput only if current can flow inside it; a rest-only gap integrates to 0 whatever its length; 0.05 A is five times below the smallest designed current (C/20 = 0.245 A); the worst-case error of a 600 s gap is below 0.5 % of the shortest cycling interval. The any-gap rule is rejected: it flags 1370 of 1893 files (72 %), 936 of them only for the designed long rest, and leaves 9 cells fully logged. Counts (recomputed by the D24 judge from `zyk_files.csv`): 18 read files are incomplete (15 with an active gap, 2 with non-monotonic time, 1 with fewer than 10 rows), in 18 cells; the 6 missing-file rows (stage 2, file 24, TP_z01_* and TP_z03_*) add 4 more cells, so 22 cells have an incomplete file and **125 of 147 cycling cells are fully logged**. A missing-file segment takes the designed throughput for its interval, the cell stays in training and scoring, and those intervals do not enter the validation. DoD classes (`DOD_CLASS_EDGES` = (0.15, 0.35)): low 0.05-0.15, mid 0.20-0.35, high 0.40-0.60; fully logged cells per class (low / mid / high): HM 15 / 9 / 38, INT 25 / 13 / 13, SIE 3 / 6 / 3, so the coverage condition (at least 2) holds, narrowly for SIE (a single SIE cell above 10 % at its last check-up rejects the analytic branch by the rule as written). The validation is run once with the ruled definition after the rebuild (C4 of D24) and is also reported, as information only, at 60 s and under the any-gap rule; the earlier 24 % median on 12 INT cells stays informational.
- **Window rule in check-up counts, from the schedule alone (FB-6 met, 17.1).** Count intermediate check-ups (CU + exCU; ET and AT excluded) per cell from the zip member listings (identifiers only). n_med = median over cycling cells; **k_cyc = round(n_med / 3)**, where `round` is Python's (halves go to the even integer; 3.5 gives 4), as implemented in `window_rule_from_counts`; likewise k_sto from storage cells 01-03.
  Primary window = first k check-ups after the reference, k in {0, 2, k_full} with **k_full = k_cyc** (section 4.1); the V3 secondary windows k_full - 1 and k_full + 2 survive as sensitivity rows at g4 only (9.9). Schedule go/no-go: cycling cells with at least 3 check-ups after a window of 4: 139 of 147 by listing and 136 of 147 after QC; 8 cells, all stage 2 (TP_z02_03, TP_z10_01, TP_z20_01, TP_z20_02, TP_z20_03, TP_z23_01, TP_z23_02, TP_z23_03), have fewer than 3, and two of them (TP_z20_02_s2, TP_z23_01_s2) have only 3 intermediate check-ups and cannot carry a window of 4; the go/no-go ("fewer than 3 for most cycling cells") is not triggered, and **the window of a cell whose number of intermediate check-ups n is not greater than the window k (k = 2 or k_full = 4) is capped at n - 1 (D025)**, so at least one post-window check-up is forecast; the cap is identical for every arm and every grid cell, mirrors the min(k, k_sto) storage rule, and the cell is kept and listed. **List corrected by D032 (`runs/freeze_runs/D025_capped_cells.md`; identifiers and counts only):** the counts of D025 were listing counts, the code's `cell.n` is post-QC; at k_full = 4 the cap binds for TP_z04_01_s1, TP_z20_02_s2, TP_z20_03_s2, TP_z23_01_s2, TP_z23_02_s2 and TP_z23_03_s2, and at k = 2 for TP_z20_02_s2 and TP_z23_01_s2; TP_z24_01_s1 and TP_z25_01_s1 stay unscoreable (window under 3 points after the incident drops of 3.3(4)); the condition-level n stays 40 at k = 4 and k = 2, so the D025 re-open condition is not triggered (scoreable cells per condition change at k = 4 for two conditions, 2 to 3 and 4 to 7). **k_full is counted from member listings before any label is read; k_full < 2 re-opens the design (J16 section 8).**

## 6. Endpoints

- **Primary endpoint (one; judge's endpoint, pp):** cell-level retention RMSE (percentage points) over the forecast set, averaged within condition (mean over the condition's scored cells) then over conditions, at the grid cell in question; Test B held-out conditions, scored on the five-seed ensemble forecast of each seeded arm (next bullet), frozen configuration. **Every primary and secondary contrast is the sign test on the log ratio of condition scores** (9.3); the pp difference is reported with every tier. Condition scores exist for each of the nine cells and each arm that runs at it.
- **Deployed predictor: the five-seed ensemble (D20 1; frozen now, no pilot gate, applied to every arm that can have it).** (1) For every arm with final-refit seeds 0-4 (A1, A2, A4/A5 and therefore AG, A9, A12, A13) the scored forecast is the mean of its five refit forecasts, per cell and per check-up, in retention space. Arms with no seed-dependent step (A10, R1, R2, the k = 0 references, and A11 if the coder confirms it is deterministic) are unchanged: one fit is their own ensemble; if A11 or A10 has a seed-dependent step it is ensembled the same way. (2) The endpoint is the cell RMSE of the ensemble forecast over the forecast set, mean within condition, then over conditions; this is the condition score S in every P-chain contrast, the secondary family, the ladder (9.6), the four downgrade rows, the lab-indicator re-runs, NC-1/NC-2, Test C, S2, Test A and the sensitivity rows. (3) A non-finite forecast is replaced seed-wise, before averaging, by the persistence forecast for that cell and counted per seed (the coder confirms the present rule is already seed-wise; if not, this sentence governs). (4) **The K chain stays single-model:** K1 and K2 use the per-seed score (mean over seeds of per-seed condition RMSE) for A1, A15 and G15 alike, because the approved sentences speak of one closed-form law; A1 therefore has an ensemble score in the P chain and a per-seed score in the K chain, and both are reported for A1 in both chains. (5) The per-seed score stays as a descriptive row beside every score, with the seed SD (section 8); the per-seed P1 and P2 counts are printed with the plain rule and labelled descriptive; they are not a downgrade row (the list (i)-(iv) of 9.8 is closed). (6) Tuning and selection are unchanged: each inner-CV trial is one fit (tuning seed 1000 + outer fold) and D\* and AG are chosen by those scores, the same for every arm; scoring five fits per trial would multiply the tuning cost by five for the neural arms and is rejected. **Printed in Methods:** the ensemble lowers each seeded arm's score by its own seed-variance share; arms with no seed variance gain nothing from it, a property of the model class; wall clock and parameter count are reported for the ensemble and for one fit, so A1, A9, AG and A12 pay five fits and A11 and A10 pay one; the mismatch between one-fit selection and ensemble deployment is disclosed. **Printed in Limitations:** the gradient arms average the data loss over points, A11 and A12 weight cells equally, A10 weights its least-squares points equally, and the endpoint weights cells within a condition and conditions equally; no arm's loss is condition-balanced, and the disparity is conservative for the PINN arms; a condition-balanced loss is a candidate for a later version, not a result (D20 3). No sentence says that ensembles or four folds are better.
- **Secondary:** the other windows of 5; error at fixed horizons after the window; RUL error in days for cells crossing 80 % (n reported); MAE, MAPE, R^2 (correct argument order); Test C, S2; wall clock and parameter count (coefficient counts for A15 and G15); share of non-finite or diverging forecasts per arm (a non-finite forecast is scored with the persistence error, seed-wise before averaging, and counted); `n_train_used` per arm and cell; `E/R_LOO` and `E/R_WARP` (descriptive, 9.10). The code writes R^2, MAPE, error by horizon and RUL error into the outer-test `metrics.json`.
- **Metrics where a regression is expected:** wall clock and parameter count; error at the first post-window check-up (a data-only learner can be locally better); RUL error (few cells reach 80 %); the worst-condition error of A1 (a median estimand does not penalise it; 9.8 rule 1).

## 7. Arms, tuning, budget (J16 1.2-1.3, section 3; D013; code README)

**Common law and recipe (D013 (a), (b), (d); README "Decisions made while building").** Law: dy/dt = [r_cal(T, SOC) + r_cyc(s) nu(t)] h(y), y_s = 10 (1 - retention), t_n = days / 500, E_n = EFC / 500. **One state factor h per fold shared by the time-driven and the throughput-driven term** ("single state-dependent modulation"; this gives the closed-form integral
y = Psi^-1(a_cal t_n + a_cyc E_n(t)), checked against RK4); it is chosen once per (outer fold, m) by a tournament on that cell's thinned training conditions only, with the same inner folds as the tuned arms of that cell, with the hard-ODE-KAN at default settings among {constant, self-limiting 1/(1 + y/Y0), accelerating exp(gamma y)} (Y0 = 1, gamma = 0.3), the simplest within one standard error of the best, and shared by all law-based arms of that cell. A result from a larger m is never reused (a tournament run at m = 32 and reused at m = 8 would leak 24 extra conditions into the law-based arms only; D20 6).
The per-cell offset delta_c scales the term(s) the cell has (the cycling term for a cycling cell, the calendar term for a storage cell), prior sd TAU = 0.15 fixed. Calendar KAN [1,2] from storage SOC to (a, E) is identical in every law-based arm; the calendar term of a cycling cell uses (T, SOC_mid); calendar twins are (T, SOC_mid) of the training cycling conditions (+ the 35 C twins in Test C). Cyclic KAN over
(T, SOC_mid, DoD, C_ch, C_dch); own compact cubic B-spline KAN (`code/models/kan_spline.py`); KAN sparsity (L1 + entropy) is computed on edge parameter magnitudes (a proxy for the activation-based penalty of the KAN literature). Stress inputs are scaled to [-1, 1] with fixed physical ranges (T 5-50 C, SOC 0-1, DoD 0-0.8, C_ch 0-1.2, C_dch 0-2.2) and clamped inside the spline grid.
Solution network F: tanh MLP width 32, depth 3, per-cell latent z_c of dimension 2, hard initial condition; fixed in every F-based arm and not tuned (conservative for the claim; A9 gets a larger space).
**Optimiser recipe (fixed constants of `law.py`, accepted as D013 (d)):** Adam, learning rate 5e-3 with cosine decay, **global gradient-norm clip 20 in every gradient-trained arm (A1, A2, A4, A5, A9, A13, A15 and every other gradient-trained arm)**, residual weight ramped from 0 to lam_res over the first 40 % of the steps in arms with a residual. The recipe was fixed after a divergence on a synthetic design (clip off: data MSE 1.7 and 34 at lam_res 0.1 and 1);
the clipped-step fraction is logged. Collocation sets: (a) record end or whole axis (tuned categorical, below), (b) Latin-hypercube points in the training hull, (c) calendar twins; causal test-time inversion (z_c, delta_c from the window plus the residual over the forecast horizon; the rule is 7.5).
**Where the recipe is a choice, not a result:** the A9/A2 clip, the 40 % warm-up and the 1e-3 grid point were set before any Samsung score; sensitivity rows (k) vary clip {10, 50} and warm-up {0.2, 0.6} for P2 at g1 and g4.

**Budget rule (J16 1.2).** Every tuned arm gets the same N trials (TPE, sampler seed = outer-fold index) at every (outer fold, m), with the inner folds of 4.1 (2 for m in {8, 16}, 3 for m = 32, unless pilot P6b adopts 4 for m in {8, 16}; grouped by condition, stratified by temperature), inside outer-training conditions only, plus 5 final refits (seeds 0-4) per arm and cell that is scored; failed trials are redrawn until N valid ones exist (more than max(2, N/4) failures raise).
**N = 40 trials for every tuned arm (D035, Shlok, 2026-11-06),** in every confirmatory, row, sensitivity and item (f) config, with the inner folds above. This supersedes the earlier rule "N = 20; N = 40 if the median fit on a Samsung training fold is under 20 s for every neural arm (J§6)", which the shake-down timing (A1 about 23-26 s) put just over its line. The doubling is symmetric (every tuned arm alike) and is fixed before any Samsung score; it changes no test, margin or outcome rule. The budget is in the config hash (`auto_budget`, `budget_rule.json`). **Timing run at the freeze commit (FB-8, open until then; D008(a), J11 C3), which now tests the Partial-plan trigger and no longer chooses between 20 and 40:** if the median hard-ODE fit exceeds 30 s or the PINN fit exceeds 90 s, the J§7 Partial plan applies to **every arm equally** (trials 40 -> 10, inner folds at m = 32 from 3 to 2, and inner folds at m in {8, 16} back to 2 if pilot P6b had adopted 4; seeds stay 5). Edge-optimum rule: a value at a grid edge extends the grid in the next version. **Value at rev. 16: N = 40 trials, with 3 inner folds at m = 32 and 2 at m in {8, 16}** (D035). The shake-down timings (`runs/freeze_shakedown/RESULT.md`, HEAD 42c2a84 code, blinded Samsung timing configs at m = 32 and m = 8; not binding): single-fit seconds A1 26.1, A2 4.6, A4 16.4, A9 5.0, A10 8.2, A10P 8.3, A11 5.5, A12 0.1, A13 24.7, A15 19.4, G15 17.2; neither the hard-ODE trigger (30 s) nor the PINN trigger (90 s) is reached, so no Partial plan is expected. **The timing run at the freeze commit (FB-8) tests the trigger**; if it fires, the Partial plan (N = 10, 2 inner folds) applies to every arm alike, and the work returns to the config step: the confirmatory configs and the five item (f) configs are regenerated and the pins of section 18 step 2 are redone before the freeze commit, because the budget is in the config hash.

### 7.5 Test-time inversion of the per-cell latents (D23)

**Status of the convention.** The development rule for the inversion (committed before the run, ISU training sides only) returned **NONE**: the second-order variant O2 failed the start-spread criterion (c) for A1 and A9. **The rule (frozen; one routine `invert_latents` for every inverting arm: A1, A4/A5/AG, A13, A15, G15 through `invert_pinn`; A9 through `predict_data_only`; A2 and the backbone tournament through `fit_delta`).**
| Element | Rule |
|---|---|
| Objective | Each arm's current per-cell loss, unchanged: window points; A1's residual over (window end, t_max] with the per-cell seeded collocation draws (n_col = 16, seed from the final-refit seed and the cell id); the priors. Causal: no label after the window |
| Arithmetic | float64 for the inversion only (a float64 copy of the trained network; the network itself is unchanged) |
| Start | The prior mode: z = 0, delta = prior mean; deterministic; a single start in production |
| Step | Per-cell Levenberg-Marquardt on the exact per-cell Hessian (block diagonal, blocks of size 1 to 4, by autograd); the damping shift makes the Hessian plus the shift positive definite; a step is accepted only if that cell's objective does not rise; damping constants fixed in code and in the config hash; no randomness |

| A10 | Unchanged (bounded Brent on [-2, 2], one dimension); cells at a bound are logged (a value at +2 or -2 means the bound set it) |

**The z-prior weight is fixed at 1 and is not tuned (D23 3).** It equals the weight of the training loss, so the test-time objective is the posterior of the model that was fitted; it is not in any tuned space of 7.1, the dimension counts of 7.1 (6, 4, 4, 5) are unchanged, and no candidate set, inner-CV choice or extra tuning budget exists. **Diagnostics (mandatory, computed after the primary scores are written, no consequence for any tier, state or sentence).** They use window labels only, as scoring does; forecasts from alternative starts are never compared with outer-test labels, no per-start score is computed in them, and nothing is selected, re-run, dropped or re-weighted because of them.

Seed stream `SeedSequence([20261105, crc32("inv|<fold>|<arm>|<m>|<k>|<j>")])`.

### 9.3 Confirmatory test: the sign test with a fixed design effect (D18 2; RES 4.4 and 9)
**Why the plain exact test is not the confirmatory test (RES 4 and 9; simulation, not a result).** Under shared fold and lab random effects with ISU-like skew and nested-subset correlation across the nine grid cells (100,000 replicates per scenario; 5 folds of 8 conditions, labs HM 17 / INT 19 / SIE 4), the plain exact one-sided sign test has size 0.0083 (28 of 40) and 0.0192 (27 of 40) for independent conditions, but exceeds 1.2 times its nominal level (0.0125, 0.025) once the intra-fold correlation of the latent log ratio reaches 0.03-0.05, or a random intra-lab correlation reaches 0.015-0.023; at intra-fold 0.10 with intra-lab 0.05 its size is 0.054 / 0.081 (4.3 and 3.3 times nominal). The D016 criterion (size <= 1.2 x nominal) is not met (RES 4.1). The pre-set fallback of this rule applied, and the gate auditor approved it before any Samsung score (D18 2.5; limits below).
**The rule (frozen).** For a contrast with n conditions and margin m let X be the number of conditions with L_c > m (ties and L_c = m are not positive; n is not reduced). Under H0, X is Beta-binomial(n; a = b = (1/rho_s0 - 1)/2) with **rho_s0 = 0.03** (a = b = 16.17; design effect 2.17). A node is rejected at local level alpha iff P(BetaBin >= X) <= alpha. No random numbers. Tier S passes m = ln 1.02; tier N passes m = -ln 1.10 but not S; "none" otherwise; "reverse tier S" passes the mirrored test (the comparator is better by the S margin: count of L_c < -ln 1.02).

## 10. Controls (D014; NC sections 3 and 6; J16 1.3)
- **NC-1 (gate G): label invariance.** Purpose: detect any flow from held-out post-window labels into predictions, tuning or selection. Procedure: every held-out cell's post-window retention is replaced by garbage (`ret_new = ret[w] - k_c (ret[w] - ret) + eps`, k_c ~ U(0.3, 2.5) per cell, eps ~ N(0, 0.02^2), clipped to [0, 1.1]; with a life level L: `ret_new = L + k_c (ret - L) + eps`, so the forecast times are unchanged and asserted),
  applied to the underlying cell object so that any copy carries the same garbage; window points and training cells untouched. **Pass iff** (a) every prediction row of the two runs (all arms, all seeds, same cells and times) is identical, max |difference| = 0 (same machine, same commit, one thread; if a platform ever breaks bitwise reproducibility the tolerance is 1e-12 and a clean-vs-clean repeat must show the same), and (b) `tuning_done.json` and
  `margins_inputs.json` are identical. Any difference trips gate G. Run (1) **before the freeze, mandatory (FB-9, open until run at the candidate frozen commit):** `mode: nc1_full` on the synthetic G2 design at Samsung size, the complete pipeline, at the candidate frozen commit, all confirmatory arms, one fold, `nc1_full.json` filed in the checklist; (2) **in every confirmatory run**, after the final predictions, each fitted arm and seed re-predicts from
  windows rebuilt out of scrambled cells and writes `invariance.json`; a difference writes `GATE_G_TRIPPED` and raises `InvarianceError`. The guard's train/test disjointness assertions (cell ids and condition keys) stay and are cited as the real-data analogue of the grouping-error leak. Evidence at demo budgets (NC§4): 0 of 9 clean datasets flagged, 9 of 9 flagged for each of two deliberate leaks.
  NC-1 is blind to what does not flow from labels through the code (human selection after looking, covariate use such as the design hull); stop rule 6 covers the former, E4 the latter. No arm reads the extent of its own forecast set (tested for all 15 arms). **NC-1 and the quality-control flag (D033 F7).** `qc_pass` is a precomputed column made upstream by a causal outlier rule (`flag_outliers`: the flag of a check-up never changes when later capacities change; unit-tested), so window labels, the anchor and the training side cannot depend on post-window labels through it. A garbage value after the window can however be flagged and dropped, which shortens the retained record: the forecast set of any cell, and the D025 window of a short cell, then depend on post-window labels through the QC. The NC-1 scramble is applied after the data build and so holds the retained set fixed by construction; a scramble upstream of the QC cannot be bit-identical for capped cells. This is a property of the design (the same dependence makes the D025 window depend on the record length) and is disclosed in Limitations.
  **Grid coverage (D033 F7).** Two checks with different reach. (1) The predict-stage check (`invariance.json`) runs in every confirmatory run and covers every (outer fold, m) run, every (m, k) prediction set, every fitted arm and every seed: each re-predicts from windows rebuilt out of scrambled cells and must reproduce its predictions exactly. (2) The full-pipeline comparison (`mode: nc1_full`) is the only check that compares tuning, selection, margins and the D\*/AG choice between a clean and a scrambled pipeline (`tuning_done.json`, `margins_inputs.json`, inner out-of-fold predictions). It runs on synthetic data only and on one fold; the mandatory pre-freeze run (FB-9) is made at the candidate frozen commit, which contains the D016 code paths (subset selector, k = 0 and k = 2 windows, A15/G15 extraction), at m = 8, 16 and 32 with at least two short-record cells, so that the D025 cap is exercised (development evidence at the D033 commit: `runs/d033_f7/RESULT.md`; it does not replace FB-9). On Samsung, tuning, selection and margins are therefore protected by the data-build rules and the guard, not by a real-data invariance comparison, and four of the five outer folds of the Samsung tuning records are never compared between a clean and a scrambled pipeline. The real-data build path (`keep` lists, first-check-up anchoring, blinding exclusions, ZYK throughput, the D025 cap, `lab_map`) is covered by a unit test that scrambles post-window capacities before the loader runs and requires byte-identical training data, cap list and windows. The synthetic Samsung-size design serves only as a data container and no G2 inference is drawn from it.
- **NC-2 (interpretive, not gating): do the stress functions carry the gain?** Run A1 (A9 optional) on the Test B folds at g4 with the stress vectors (each cell keeps its own throughput and window) permuted among conditions, separately in training and test (`permute_stress`, Test B only: a derangement of the stress vector within the set; the cell's own throughput, times, retention and window are kept), and compare with the real g4 run: L_c = ln(S_A1,permuted,c / S_A1,real,c), paired by condition. The freeze commit is the commit that contains the final prereg text, the splits, the configs and the code. (`PREREG_DEFAULT` in `guard.py` names `runs/prereg/PREREG_v3.md` since commit ca66522; it is changed to the final file (section 20) or `build_freeze_payload` is called with `prereg_file` set to the final file, e.g. `runs/prereg/PREREG_v4.md` or its frozen successor, and FROZEN stores that name.)
4. **Who writes FROZEN.** **The lead** (not the experiment designer, not the statistician, not any code): after the signatures. Nothing in the package writes the file. The lead calls `guard.build_freeze_payload(root, split_keys, config_paths, prereg_file)` with `split_keys = [("samsung","B"), ("samsung","C"), ("samsung","S2"), ("samsung","A"), ("isu","B"), ("snl","B")]` (plus A/S3 entries as run) the list of confirmatory config paths, the prereg file and `item_f_config_paths` (the five item (f) configs of step 2b; `require_pins=True` requires five entries), and writes the returned dict as JSON to `runs/prereg/FROZEN`.
5. **FROZEN fields** (from `build_freeze_payload`): `commit` (git rev-parse HEAD at the call), `prereg_file`, `prereg_sha256`, `splits` = {"<dataset>:<test>": {`file_sha256`, `fold_hash`}}, `config_sha256s` (canonical hashes of DEFAULTS merged with each config file), `item_f_config_sha256s` (the same for the five item (f) configs). The file is committed in the same step only if the commit is the frozen commit itself; the simplest order is: commit everything, call the payload builder, write FROZEN as an untracked flag file (the guard checks tracked files only), run `verify_freeze`. HEAD must then not move until all confirmatory runs finish (a later commit invalidates the freeze, by design). D031 (procedural): FROZEN is written and every confirmatory run executes in the main checkout of the project; later work (manuscript, figures) goes on a branch in its own worktree.
6. **What the guard then enforces.** `verify_freeze`: FROZEN present; prereg hash equals the pin; HEAD = commit; tracked files under `code/` and `runs/prereg/` clean. `load_split(role="test")` and the scorer call it; the split file and fold-hash pins are checked on every load (training role too); a confirmatory real-data run needs its canonical config hash in `config_sha256s`, `steps_scale = 1`, no `overwrite`, and is appended to
   `runs/prereg/SCORED.jsonl` (a second scoring of the same config is refused; a folder holding `condition_scores.json` is never replaced). Samsung un-blinds only on a valid freeze. At run start `DeviceError` is raised if CUDA is visible.
6b. **Item (f), by state (D026).** After `verify_freeze` passes and before any Samsung test fold is loaded, in this order: (i) run the five item (f) inner runs (g1, folds 0-4; `role = "train"`); (ii) run `stats_v4.build_item_f`, which writes `runs/item_f/item_f_dependence.json` and its `.sha256.json` record and refuses on the conditions of 9.9 (r); (iii) only then start the confirmatory runs, each of which calls `guard.require_item_f_record` before `build_data` and writes `item_f_sha256` into its `SCORED.jsonl` row. Re-open conditions are listed in 9.9 (r); a re-opened item (f) is a new version with a change-log row (stop rule 7), not an edit after scoring.
7. **After scoring.** Run the statistics step (`code/run_pinnkan_stats.py`) on the fold runs; the figure scripts read its outputs. Any rule change after a Samsung test fold is scored is a new version with a change-log row and a disclosure (stop rule 7).
